# 任务台使用说明

> 适用版本：**v0.35.0 及以后**（v0.34.x 及更早版本有"两个出口"，见 §1 的历史说明）
> 相关页面：**任务台**（发起、看历史）、**模型配置 → ④ 执行器**（配置被调度的一方）、
> **按键重映射**（绑定槽位）、**设置 → 任务台**（总开关 / 播报 / 外部会话监工）

---

## 0. 一句话定位

**任务台要解决的问题只有一个：Agent 干活要几十秒到几十分钟，而你的注意力不能一直挂在终端上。**

它把"人盯着终端等结果"换成"系统替你等着，干完了喊你"。
所以你不需要为了不丢结果而坐在那儿；也不需要因为走开了而错过结果。

要兑现这句话，需要**两半**，缺一不可：

| 一半 | 干什么 | 谁来做 |
|---|---|---|
| **异步 + 通知** | 说完就走；跑完语音播报结论，有产物自动打开 | 后台队列 + 播报层（§3.3、§3.5） |
| **可追溯** | 事后能查清"那次到底做了什么、完整输出在哪" | **任务历史**（§3.6） |

只有前半句，用户仍然不敢走开——因为**走开就意味着过程永久丢失、无从复盘**。
所以 v0.35.0 把这两半一起补齐了。

## 1. 一条路：按键和页面按钮都进后台队列

### 现在的行为

按 **S1–S4** 说话，和在同名槽位上点 **「派发到该槽（后台执行）」**，
**走的是同一条代码路径**（`agent_desk::dispatch_task`），后果完全一致：

- 任务进该槽的**队列**（同槽串行、跨槽并行、深度上限 8）
- 在**后台独立子进程**里跑，**过程不占你的屏幕**
- 跑完按**四档完成信号**判完成，可选由**世界门禁**复核
- 完成后：**语音播报结论** → 有产物就**自动打开** → 产生**未读**（该槽灯亮）
- 全过程写进**任务历史**，随时可查

按键只比页面多一件事：**它替你按了"派发"这个动作**（并把识别出的文本送进去）。

> **按 S1–S4 说话时的字幕**：识别出的文字会显示在跟随鼠标光标的**字幕浮层**上，
> 并**停留约 1.8 秒**再收起。停留是有意为之 —— 任务台**不会**把内容写进任何输入框，
> 浮层是你唯一能确认"我这句话被识别成了什么"的地方。
>
> ⚠️ 浮层空白时先查两处：① 「设置 → 后台字幕浮层」开关是否打开；
> ② 识别服务是否在收尾前就报了错。后端的识别成功记录在日志里搜「语音：识别成功」。

### 历史说明：为什么删掉了「出口 A」

v0.34.x 有两个出口。出口 A 是"按一下键 → 系统用同一份参数模板拼出完整命令行
→ **投进你正在用的那个终端**"。它唯一的卖点是**过程可见**。

删掉它，是因为这条卖点与任务台的价值正好相反，代价却是它**绕开了整套机制**：

| 出口 A 缺什么 | 后果 |
|---|---|
| 队列 / 同槽串行 / 去重 | 同一槽连按两次 = 两个 Agent 同时在烧 token |
| 四档完成判定 + 世界门禁 | "跑完了"只能靠你肉眼判断 |
| 超时回收 | Agent 卡住时没有任何回收点 |
| 结果回读与播报 | 你得回到那个窗口去看 |
| 未读账本与灯 | 换个房间回来，不知道期间发生了什么 |
| 多轮会话续接 | 每次都是新对话，你说"那刚才那个呢"它答不上来 |

更要紧的是最后一条组织性后果：**按键和页面按钮跑的不是一回事，而用户有理由相信它们一致**。
两条路径的差异不是"风格不同"，是"能力不同"，这会在最需要信任的时刻（比如"我明明按了它怎么说没做"）爆出来。

### 删掉它的代价（诚实说）

**过程不可见了。** 后台执行时，跑的过程中你**看不到任何输出**。
（进度出口目前仍被丢弃 —— 见 §6。）

补偿手段是**任务历史**（§3.6）：过程仍然不留，但**完整输出会被完整落盘**，
你可以事后一遍看完，而不是盯着它一行行爬。这是刻意的取舍：

> **守着看**是"用你的注意力换即时感"；**历史**是"用磁盘换你的注意力"。后者才是可规模化的那一边。

## 2. 设计用途：为什么要这么设计

按第一性原理拆，这套机制是被四条无法回避的事实**逼出来**的。

### 事实 1：Agent 任务的耗时量级变了

一次 HTTP 请求是秒级；一次 CLI Agent 任务是**分钟级**（本机实测 codex 跑一个真实任务
常在中位数几分钟，长的十几分钟）。耗时一旦超过人的耐心阈值，"守着看"就变成纯浪费。
⇒ 需要**异步 + 通知**，而不是同步等待。

### 事实 2：「进程退出」不等于「任务完成」

这是整套设计的地基，也是它区别于"手敲命令看返回值"的核心。

- `exit code = 0` 只说明**进程正常结束了**，不说明**事情办成了**。
- 一个 Agent 完全可能成功退出但什么都没改；也可能失败退出却已经把文件改了一半。

⇒ 所以有了 `CompletionKind` 四档判定，以及**世界门禁**（`evidence_cmd`）：
让一个**外部命令**（跑测试、查文件、验产物）来裁决"到底做成了没有"。
门禁不通过时，状态会从 `已完成` **翻成** `失败`——宁可承认失败，也不播报成功。

### 事实 3：一个槽位 = 一个按键 + 一颗灯 + 一段播放，都是**单份资源**

按键只有一个、灯只有一颗、喇叭同一时刻只念一句话。
如果同槽并发跑两个任务，就会出现"灯该亮哪个""喇叭念谁的结果""按下键取消哪一个"全说不清。

⇒ 所以**同槽严格串行**（后面的排队），**跨槽才并行**（每个槽有自己独立的按键和灯）。
队列深度硬上限 **8** 条/槽，到顶**明确报错**而不是静默丢任务。

### 事实 4：多轮对话必须靠会话 id 才接得上

CLI Agent 每次调用默认是**全新会话**。第二轮问"那刚才那个呢"，它答不上来——因为它根本没见过上一轮。

⇒ 所以有了会话续接：从输出事件流里抓出会话 id，下一轮把它拼回去
（codex 是 `exec --json --skip-git-repo-check resume <id> "<prompt>"`）。
会话按**槽位**记忆并持久化，重启应用也不丢。

### 事实 5：「它产出了什么」只能从文件系统看

任务完成后要"自动打开产物"，判据是什么？能被外部观测到的只有一件事：
**文件 mtime 变了**。另外两条路都试过并否掉了：

- **解析 Agent 的输出** —— 各家格式不同，而且它输出的是"我打算写 XX"，
  这是**意图**不是**事实**（它可能写完又删了，或者根本没写成）。
- **让用户预先配产物路径** —— 那就等于让用户替程序记笔记，
  而且任务千变万化，配不过来。

⇒ 所以判据是**时间窗 + 可选 glob**（§3.4）。它有原理性局限（见 §6），
但它是唯一"不需要用户额外付出、且不可被 Agent 的话骗过"的判据。

## 3. 怎么用

### 3.1 前置：先有一个能用的执行器

打开 **模型配置 → ④ 执行器**。出厂预置三条：

| 执行器 | 形态 | 完成判定 | 出厂是否启用 | 说明 |
|---|---|---|---|---|
| 豆包 API（火山方舟） | API | HTTP 流结束（**已校验**） | 启用 | 需填模型（方舟接入点 `ep-...` 或模型名）+ API Key |
| Codex CLI | CLI | 日志命中 `turn.completed`（**已校验**） | **未启用** | 命令必须写 `codex.cmd`（裸名 `codex` 在 Windows 上起不来）；已配会话续接 |
| DSH（DeepSeek Harness） | CLI | 进程退出码 0（**未校验**） | **未启用** | headless 模式**不支持**跨调用续跑，所以没配续接；指令含糊时会主动提问而无人应答，会 fail closed |

要新增自己的模型：点 **「+ 添加模型」**（API 型，只需端点 / 模型 / Key 三个字段）
或 **「+ 添加 CLI 执行器」**（需要命令 + 参数模板，参数里**必须**有 `{prompt}`）。

配完点 **「保存合成与执行器配置」**，再点该行的 **「探测」** 确认配置能被调度。

> **建议给 CLI 执行器配上世界门禁。** 没有门禁的 `ProcessExitZero` 只能给出"未校验"的可信度——
> 系统会照常播报，但它说的"已完成"其实只是"进程退出了"。
> 任务历史里也会把这类条目标成 **未校验**，一眼能看出来。

**两个产物相关字段**（在 CLI 执行器的**「高级选项」**里，v0.35.0 新增）：

| 字段 | 作用 | 建议 |
|---|---|---|
| **产物过滤** | 可选通配，用来在时间窗命中的文件里再筛一层 | 留空 = 不筛。要筛就写**相对工作目录**的路径，如 `out/*.png`、`**/*.md`、`*.pdf` |
| **成功时自动打开产物** | 任务成功后自动帮你打开产物 | **默认开**。它只在"任务成功 且 确实扫到文件"时才动作 |

### 3.2 绑定槽位

**按键重映射 → 把某个键的「类型」设为「任务台」→ 选 S1…S4 → 选执行器。**

- 每条按键的绑定方式目前**只支持「指定执行器」**（见 §6）。
- 绑定改完**立刻落盘**，不需要额外保存。
- 槽位与执行器是**多对一**：多个槽可以共用同一个执行器（但每个槽有自己独立的会话）。

### 3.3 发起任务：按键，或页面「派发到该槽」

**用按键：**

1. 按下绑定任务台的键，说话。**再按一次结束录音**（按键是 toggle，不是按住说话）。
2. 识别结果直接**进后台队列**。屏幕提示会告诉你"已开始执行（任务 #N）"或"已排队（前面还有 N 条）"。
3. 然后你就可以走开了。**不需要打开终端，也不需要盯着任何窗口。**

**用页面：**

1. 打开 **任务台** 页面。
2. 在「槽位」下拉里选一个**已绑定且可调度**的槽位。
3. 写任务内容（**可以直接打字，不必走语音**）。
4. 点 **「派发到该槽（后台执行）」**。
5. 页面上还能做：**取消排队** / **取消执行** / **新起一轮对话**（丢掉该槽会话 id，
   下一条就是新话题）/**清空待执行**。
   - **「取消执行」会终止这条任务的整棵进程树**，半秒左右生效。
     入口有两个、动作是同一个：**运行中任务卡右边的 `×`**，以及槽位下方的「取消执行」按钮。
     按下后按钮显示「取消中…」，等它**真的停下来**才恢复。
   - 「终止整棵进程树」是必须的：CLI 执行器的真实进程结构是
     `cmd.exe`（外壳）→ `node.exe`（干活的）。只杀外壳的话，`node` 会继续改文件、
     继续烧 API 额度，还会攥着输出管道不放 —— 任务看起来"取消不掉"。

**跑完之后，系统会主动做三件事：**

1. **语音播报结论**（PC 喇叭出声）——念的就是这次任务的结论，不是一句干巴巴的"任务已完成"。
2. **有产物就自动打开**——只扫到 1 个文件就直接打开它；多个就打开所在文件夹并选中最新的那个。
3. **产生未读**（该槽灯亮）——按一下该槽的键，或到页面点「播报未读」，听完整结果。

> ⚠️ **自动打开只发生在"任务成功"那一刻。** 失败、超时、取消的任务**不扫产物** ——
> 那时目录里留下的是半成品（写到一半的导出、没封口的容器），把它当"产物"打开是主动误导。
> 想看那些任务的输出，用任务历史（§3.6），那里有完整日志。

#### 3.3.1 播报念什么：三项设置真的生效了

**设置 → 任务台 → 「总结与播报」**：

| 设置 | 作用 |
|---|---|
| **摘要字数上限**（默认 180） | 播报正文的长度上限。TTS 念 180 字约 30 秒——再长你就等不下去了（还想按别的键） |
| **总结执行器** | **留空 = 不二次总结**，直接念 Agent 自己的结论；非空 = 用那个执行器再跑一次，把结果压成更凝练的一句 |
| **总结失败退回原文截断原文** | 打开（默认）= 总结不出来就念原文截断；关掉 = 只念固定语料 |

**关于「总结执行器」为什么默认留空：** CLI Agent 交回的**最后一句**本就是它给自己做的总结。
再套一层模型不会让它更准，只会更慢、更容易跑偏（把"微信已启动"扩写成三句客套话）。
所以默认念 Agent 的原话，不额外花钱、不额外等。

**总结不占槽位、不阻塞下一条任务**：它是后台另起的一次调用（几秒到几十秒）。
排在后面的任务不会被这句"润色"卡住。

### 3.4 产物发现：判据是「时间窗 + 可选 glob」

任务成功后，系统会在该执行器配的**工作目录**里找"这次任务动过的文件"：

- **时间窗**：只收 `mtime ≥ 任务开始时刻` 的文件。这是主判据。
- **glob**（可选）：在时间窗命中的文件里再按名字筛一层。
  - `*.md` —— **只命中工作目录根下**的 markdown
  - `out/*.png` —— 命中 `out` 目录里的 png
  - `**/*.md` —— 命中**任意深度**的 markdown
  - `*` **不跨目录分隔符**（这是刻意的：你写 `*.md` 时想的是"当前目录的 markdown"，
    而不是"任意深度的所有 markdown"；要跨层就写 `**`）
- **上限**：深度 4 层、最多访问 4000 个条目。超限会**如实报告**（日志里写明"已达条目上限被截断"），
  不假装扫完了。
- **跳过**：版本库 / 依赖 / 缓存目录（`.git`、`node_modules`、`target`、`.venv`、`.cache` …）不进去扫。
  **跳过了几个目录会写进日志** —— 这样"没扫到产物"的两种可能（真没有 / 全被跳过了）你能区分。

> **`out/` `build/` `dist/` 不在跳过名单里。** v0.35.0 特意把它们移出去了：
> 当初把它们当"构建产物目录"排除，是拿别人的习惯替你做了决定 ——
> 而大量工具（Go / Julia / 推理导出 / 报告脚本）恰恰把成果写进 `out/`。

### 3.5 外部会话监工：给"你自己开终端跑 codex"补一句播报

这一条针对的是**另一个场景**：你在**自己的终端**里跑 codex（不经过任务台），
过程你看得见，但**你走开了没人告诉你跑完了**。

**外部会话监工**补的就是这个缺口：它盯着 `%USERPROFILE%\.codex\sessions\**\rollout-*.jsonl`，
看到一轮跑完就把结论接进通知层播报。

- 开关：**设置 → 任务台 → 外部会话监工**（出厂默认**开**）。
- 没装 codex 时根目录不存在，等于零副作用。
- 启动后**第一轮只登记偏移不播报**（否则会把历史会话当成新事件播一堆）。
- 它**不产生未读**——只播一句，不占未读灯。
- 它播的是**固定语料**（"任务已完成"），不念那句话的正文；
  正文只上屏作为字幕（见下面的说明）。

> **一句话区分：** 任务台管"我说给它听的活"；外部会话监工管"我自己在终端里跑的活"。
> 两条路都在跑完时出声，这是唯一的目的——**你不需要盯着任何一个窗口。**

### 3.6 任务历史：异步的前提

打开 **任务台** 页面，向下滚到 **「任务历史」**。这里回答的就是"走开"之后你还想知道的所有事。

列表显示**最近 50 条**（最新在前），每条一行：

- 槽位（S1–S4）
- 结果状态（`已完成` / `失败` / `超时` / `已取消`）
- 完成是否经**世界门禁校验**（未校验的会挂一个 `未校验` 标签 ——
  "进程结束了"不等于"事情做成了"，这两件事必须一眼分得开）
- 你当时的**原话**、开始时间、跑了多久、用的哪个执行器、产物数量

**点一行展开**，能看到：

- **原话**（完整的那句）
- **失败原因**（失败时才有）
- **续接的会话 id**（下一轮会接着这段对话）
- **产物清单**（绝对路径；成功的任务已经自动打开过了）
- **输出尾部**（一眼看结论）
- **完整日志**（该任务的全部输出，单独一个日志文件）

**磁盘上留 200 条**，位置：**「产物目录」下的 `tasks/`**。

> ⚠️ 不是 `%APPDATA%`。任务史和 `slot_sessions.json`、`notice_assets/` 一样，
> 都落在**任务台设置里的「产物目录」**下面（那个目录就是这个 App 的输出根）。
> 只有在「产物目录」**留空**时才会退回默认的 `%APPDATA%\com.easyop.app\agent_desk_out\`。
> 本机的「产物目录」被设成了 `E:\MY_AI\CLI`，所以实际路径是 **`E:\MY_AI\CLI\tasks\`**。

```
<产物目录>/tasks/
  index.jsonl                          ← 一行一条记录（列表页读它）
  1758591234567_s1_t18.log             ← 任务 #18 的完整输出
  1758594890123_s2_t19.log
  ...
```

清理规则：超过 200 条时**从最老的开始删，并连同它的 `.log` 一起删**。
不会只删索引留下孤儿日志（那正是"日志目录悄悄膨胀"的成因）。

> ⚠️ **历史是"跑了什么"的记录，不是"当前在跑什么"。** 队列和未读**刻意不持久化** ——
> 重启后队列为空。原因：重启前那些任务的子进程已经不存在了，
> 恢复一条"正在执行"的任务是**假象**（它会永久卡在那儿）。历史则相反，它是既成事实，必须留住。

## 4. 和「手动开终端 + 语音键输入 + 回车」到底差在哪

**"全程手动"指**：自己开终端 → 用语音键把话**当普通文本上屏** → 自己读一遍 → 自己回车。

| 维度 | 全程手动（语音上屏） | 任务台（按键 / 页面派发） |
|---|---|---|
| 命令由谁拼 | **你自己**（说错就上屏了错字） | 系统按执行器的参数模板拼 |
| 拼装错误的风险 | 高（同音字、漏参数） | 低（模板固定） |
| 多轮上下文 | 自己记住 / 手动加 `resume` | ✅ 同一槽位自动续接 |
| 过程可见 | ✅ 全可见 | ❌ **不可见**（这是唯一的短板） |
| 结果是否可靠送达 | ❌ 你得盯着 | ✅ 播报 + 未读 + 灯 |
| "真的做成了吗" | 你自己判断 | ✅ 完成判定 + 可选世界门禁 |
| 超时 / 取消回收 | 你自己 Ctrl+C（还可能漏掉子进程） | ✅ 超时自动 kill；**取消会终止整棵进程树**（实测 0.5 秒停住） |
| 排队 / 去重 / 取消 | 无 | ✅ 有（同槽串行，深度上限 8） |
| 同时跑多个 | 靠多开终端 | ✅ 跨槽并行 |
| 换个设备 / 离开电脑 | ❌ 等不到 | ✅ 状态在未读账本里，历史在磁盘上 |
| **事后可追溯** | 靠终端 scrollback（关了窗口就没了） | ✅ **任务历史：完整输出独立落盘，留 200 条** |
| 完成后自动开产物 | ❌ | ✅ |

### 三条别人给不了的优势

1. **"成功"这个结论经过校验。**
   不是"进程退出了就说成功"，而是完成信号 + 可选的世界门禁共同裁决。
   未经校验的条目在历史里标着 `未校验`，不糊弄你。

2. **多轮任务能接着上下文跑。**
   同一槽位的第二条任务会自动带上 `resume <id>`，接着上一轮对话——
   手动做法里你得自己复制粘贴会话 id。

3. **不占用你的注意力。**
   跨槽并行 + 播报 + 未读灯 + 自动开产物 + 可查历史，让你可以一次性丢几件事出去，
   回来听结果、翻历史就够了。

### 代价（诚实说）

- **过程不可见。** 跑的过程中看不到任何输出（进度出口被丢弃）。这是删掉出口 A 时明确接受的代价，
  补偿手段是任务历史：**过程不留，但完整输出会被完整落盘**。
- **失败不会自动重试**（唯一的例外：会话续接疑似失效时会丢掉 id 重跑一次）。
- **产物判据有原理性局限**（§6 第 3 条）。

## 5. 排错：常见报错与对策

| 报错 / 现象 | 原因 | 对策 |
|---|---|---|
| `槽位 S1 未绑定执行器` | 该槽没绑 | 按键重映射 → 类型=任务台 → 选执行器 |
| `槽位 S1 绑定的执行器 xxx 不存在（可能被删了）` | 执行器被删了 | 重新绑定；删除执行器时系统会连带清空引用它的槽位 |
| `槽位 S1 的执行器「xxx」不可调度：未启用` | 执行器 `enabled = false` | 到「模型配置 → ④ 执行器」把开关打开 |
| `…不可调度：配置不完整（缺 API Key 或命令）` | API 缺 Key/模型，或 CLI 缺命令 | 补齐对应字段 |
| `…不可调度：<具体错误>` | 校验硬错误（如 CLI 参数缺 `{prompt}`） | 按提示改；错误里会点名**具体是哪一条不满足** |
| `S1 没能派发：…（你的原话：…）` | 派发被拒（槽未绑 / 不可调度 / 队列满 / 重复） | 按括号里的原因处理。**失败绝不退回上屏** —— 原话只留在提示里，不会粘到你当前窗口 |
| `槽位 S1 用的是「按能力」绑定，但能力路由尚未实现（Phase 4）` | 绑定方式选错 | 改成「指定执行器」 |
| 任务超过 3 分钟被判超时 | 用了默认超时（180 秒），而那是照 HTTP 调用定的 | CLI 型执行器把「单次执行超时」调到 **900000**（15 分钟）或按需 |
| 灯亮了但按下去没声音 | 该槽没有未读结果文本 | 未读与播报是两套；确认任务是否真的完成（取消不产生播报正文） |
| **点了「取消执行」，任务好像还在跑** | 取消是"置标志 + 收尾"，不是瞬时动作；收尾要起一个 `taskkill` 并结束两个行读任务 | 正常在 **0.5 秒**内停住（按钮会先变「取消中…」）。若超过 2 秒还没停，看日志：有 `runner 已终止整棵进程树 pid=…` 说明树被杀掉了；有 `runner 收尾超时` 说明进程树没杀干净（会**如实记日志**，绝不静默挂着） |
| **取消后进程列表里还有 `node.exe`** | 若那条任务还在跑别的槽位的活儿，正常 | 取消只终止**这一条任务**的进程树，不碰其他槽位的任务 |
| **任务跑完了，但没打开任何产物** | ① 执行器没配「工作目录」⇒ 系统**不扫盘**（绝不拿 easyop 自己的目录顶替）② 产物 mtime 落在时间窗外 ③ 被 glob 筛掉了 ④ 任务未成功 | 看日志里那行 `任务台产物：在 <目录> 扫到 N 个新文件…（共访问 N 个条目，跳过 N 个目录）` —— 四个数字能直接定位是哪一种 |
| **历史列表里没有刚跑完那条** | 历史面板每 10 秒刷新一次 | 等 10 秒，或点标题右侧的「刷新」 |
| **历史里点开某条，完整日志是空的** | 该任务的日志文件被清理了（200 条上限），或当时写盘失败 | **这不代表任务失败** —— 任务本身已按列表里的状态结束了。日志写失败只记日志，绝不反过来把任务判失败 |

## 6. ⚠️ 当前未实现的能力（已知边界）

写在这里是为了**避免你按着说明书去用不存在的东西**。以下都是 UI 上可能看得到、
但运行时尚不可用的：

| 项目 | 状态 |
|---|---|
| **「按能力」/「自动判定」槽位绑定** | ❌ 未实现（Phase 4）。选了会在派发时报错。`Capability` 目前只用于 UI 上显示"有几个候选" |
| **完成信号 `AsyncTaskPoll`**（异步任务轮询） | ❌ 未实现，校验层直接拒绝保存这种配置 |
| **逐行执行日志（跑的过程中实时显示）** | ❌ 没有。后台执行的进度输出仍被丢弃。**但完整输出会在跑完后落进任务历史** |
| **失败自动重试** | ❌ 没有（仅"续接失效"会降级重跑一次） |
| **从历史面板"打开产物"** | ❌ 没有。自动打开只在任务成功那一刻发生；从历史里点开一个**旧**产物目前做不到。（后端也没有"打开任意路径"的命令，出于不扩大攻击面的考虑先不加） |
| **`stderr` 单独落盘** | ⚠️ **部分**：日志格式支持一段 `----- stderr -----`，但 `RunOutcome` 目前没有 `stderr` 字段 ⇒ 实际**永远是空的**。失败原因只在"原因"那一行里、且已被截断 |
| **键盘喇叭出声** | ❌ 未做，目前只从 **PC 喇叭**出声 |
| **开发板灯语（命令 `0x16`）** | ⚠️ 两侧已通，**固件未烧**，暂时看不到灯效 |

> 上面最后两项属于"知道但没落地"，不是 bug。其余每一项都会在后续版本里补。

**产物发现的两条已知局限**（不是 bug，是这个判据的固有性质）：

1. **任务期间由别的程序写进同一目录的文件，也会被算成产物。**
   时间窗只认 mtime，它分不清"是谁写的"。所以别拿一个同时有别的程序在写文件的目录当工作目录。
2. **"没找到产物"和"任务没产出"在界面上长得一样。**
   缓解手段是日志里那行统计（扫了多少条目、跳过多少目录、是否被截断），
   以及可以选择性地配 glob 把范围收窄。

## 7. 快速上手清单（5 分钟）

```
1. 模型配置 → ④ 执行器：确认 Codex CLI 已「启用」，填好「工作目录」，
   点「探测」确认可调度。（工作目录必须填，否则产物发现不会扫盘）
2. 按键重映射：给某个键设「类型 = 任务台」，选 S1，执行器选 Codex CLI
3. 任务台页面：文本框写「列出当前目录下最大的 5 个文件，并按大小排序」
4. 点「派发到该槽（后台执行）」→ 走开
5. 听到播报 → 回来滚到「任务历史」：点开那一条，能看到原话、耗时、输出尾部、完整日志
6. 想接着问就再派一条：「那把第 2 个删掉」——它会带着上下文接着跑
```

第 6 步是这套机制最值钱的地方：**它记得你们上次聊到哪。**

第 5 步是这一版新增的：**你走开之后发生的每一件事，都留得下痕迹。**
