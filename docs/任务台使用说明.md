# 任务台使用说明

> **适用版本：v0.41.x 线**（最后对照代码核对：2026-10-13，v0.41.14）  
> 本文面向**使用者**。实现原理与设置项全量清单看  
> `docs/任务台设计方案.md`（含每个参数的代码位置）。
>
> 相关页面：
>
> - **任务台**（发起、看运行时、看历史、调试工具）
> - **模型配置 → ③ 语音合成 / ④ 执行器**（配置被调度的一方）
> - **按键重映射**（把键绑到槽位）
> - **设置 → Agent 任务台**（总开关 / 总结与播报 / 外部会话监工）

## 0. 一句话定位

**任务台要解决的问题只有一个：Agent 干活要几十秒到几十分钟，而你的注意力不能一直挂在终端上。**

它把"人盯着终端等结果"换成"系统替你等着，干完了喊你"。  
所以你不需要为了不丢结果而坐在那儿；也不需要因为走开了而错过结果。

要兑现这句话，需要**两半**，缺一不可：

| 一半          | 干什么                    | 谁来做                   |
| ----------- | ---------------------- | --------------------- |
| **异步 + 通知** | 说完就走；跑完语音播报结论，有产物自动打开  | 后台队列 + 播报层（§3.3、§3.5） |
| **可追溯**     | 事后能查清"那次到底做了什么、完整输出在哪" | **任务历史**（§3.7）        |

只有前半句，用户仍然不敢走开——因为**走开就意味着过程永久丢失、无从复盘**。

## 1. 一条路：按键和页面按钮都进后台队列

按 **S1–S4** 说话，和在同名槽位上点 **「派发到该槽（后台执行）」**，  
**走的是同一条代码路径**（`agent_desk::dispatch_task`），后果完全一致：

- 任务进该槽的**队列**（同槽串行、跨槽并行、深度上限 8）
- 在**后台独立子进程**里跑，**过程不占你的屏幕**
- 跑完按**四档完成信号**判完成，可选由**世界门禁**复核
- 完成后：**语音播报结论** → 有产物就**自动打开** → 产生**未读**（该槽灯转绿=待播，亮度随未读数分档）
- 全过程写进**任务历史**，随时可查

按键只比页面多一件事：**它替你按了"派发"这个动作**（并把识别出的文本送进去）。

> **按 S1–S4 说话时的字幕**：识别出的文字会显示在跟随鼠标光标的**字幕浮层**上，  
> 并**停留约 1.8 秒**再收起。任务台**不会**把内容写进任何输入框，  
> 浮层是你唯一能确认"我这句话被识别成了什么"的地方。
>
> ⚠️ 浮层空白时先查两处：① 「设置 → 后台字幕浮层」开关是否打开；  
> ② 识别服务是否在收尾前就报了错（日志搜「语音：识别成功」）。

### 历史说明：为什么删掉了「出口 A」

早期版本（v0.34.x）有两个出口。出口 A 是"按一下键 → 拼出完整命令行 →  
**投进你正在用的那个终端**"。它唯一的卖点是**过程可见**，  
但代价是它**绕开了整套机制**：队列、完成判定、超时回收、未读、续接全没有，  
而且**按键和页面按钮跑的不是一回事**——这会在最需要信任的时刻爆出来。  
v0.35.0 起删除，只保留现在这一条路。

### 删掉它的代价（诚实说）

**过程不可见了。** 后台执行时，跑的过程中你**看不到任何输出**  
（进度出口目前仍被丢弃 —— 见 §6）。

补偿手段是**任务历史**（§3.7）：过程仍然不留，但**完整输出会被完整落盘**，  
你可以事后一遍看完。这是刻意的取舍：

> **守着看**是"用你的注意力换即时感"；**历史**是"用磁盘换你的注意力"。

## 2. 页面导览：任务台页面有什么

打开**任务台**页面，从上到下六块：

| 区块             | 看什么                                                         | 能做什么                              |
| -------------- | ----------------------------------------------------------- | --------------------------------- |
| **页首状态卡**      | 就绪灯、总开关徽标、执行中槽数、未读数、未就绪原因（blockers）、TTS 三态、产物目录、配置路径        | 刷新 / 去模型配置 / 去设置                  |
| **槽位（S1–S4）**  | 每槽一张卡：模式、正在执行的任务（`#id` + 摘要 + 耗时 + 执行器）、排队任务、未读/播放中徽标       | 取消执行（终止整棵进程树）/ 撤掉排队任务             |
| **运行时**        | 三态灯（空闲待命 / 正在执行 / 有积压却没任务在跑）、执行中、待执行、未读、喇叭持有者、累计完成/失败、活跃执行器 | —                                 |
| **调试工具**（默认收起） | 手动派发、播放租约（模拟"按键播放"）                                         | 派发 / 新起一轮 / 清空待执行 / 取租约 / 回执 / 释放 |
| **播报**（默认收起）   | 预合成语料就绪情况、离线可用性、最近一次播报、播报未读完整链路                             | 预合成全部语料 / 试听 / 播报未读 / 丢弃未读        |
| **任务历史**（默认收起） | 最近 50 条记录 + 每条完整日志                                          | 展开详情 / 手动刷新                       |

**数据刷新节奏**：配置 5 秒、运行时 1.5 秒（另有事件推送）、历史 10 秒。  
所以"刚跑完的任务还没出现在历史里"是正常的，等 10 秒或点「刷新」。

**灯语对照**（开发板，需固件烧录 `0x16`，**已烧且已实测通过**，见 §6）：  
第 1–4 颗 = **各槽状态，四选一**（互斥，优先级 播放 > 执行 > 待播 > 空闲）：

| 颜色 | 状态 | 含义 |
|---|---|---|
| 蓝 | **执行** | 任务已下发，正在跑 |
| 青 | **播放** | 喇叭正在念这个槽的结果 |
| 绿 | **待播** | 有未读等你听（**亮度三档**：1–3 / 4–6 / ≥7 依次变亮） |
| 灭 | **空闲** | 没事（全灭） |

第 5 颗 = **按键反馈**：按下任一任务台键时闪 120ms 作输入确认，闪完即灭（平时全灭）。

> ⚠️ **"亮着"就是"有状态"，不再是"在执行"**（v0.43.0 改的，旧文档写反了）。  
> ⚠️ 未读数**不直接显示**，只通过待播灯的**亮度档位**间接表达。  
> ⚠️ 灯**完全不亮**先别怀疑代码：让开发板**重新枚举**（关机再开机 / 拔插 USB）再试。  
> Windows 会缓存 HID 报告描述符，固件更新过描述符但设备没重新枚举时，
> 主机侧会报"参数无效"，表现成"灯怎么都不动"，但代码是好的。

## 3. 怎么用

### 3.1 前置：先有一个能用的执行器

打开 **模型配置 → ④ 执行器**。分两组管理：**直连模型（API）** 和 **CLI 执行器**。  
出厂预置三条：

| 执行器                   | 形态  | 完成判定                           | 出厂是否启用  | 说明                                                       |
| --------------------- | --- | ------------------------------ | ------- | -------------------------------------------------------- |
| 豆包 API（火山方舟）          | API | HTTP 流结束（**已校验**）              | 启用      | 需填模型（方舟接入点 `ep-...` 或模型名）+ API Key                       |
| Codex CLI             | CLI | 日志命中 `turn.completed`（**已校验**） | **未启用** | 命令必须写 `codex.cmd`（裸名 `codex` 在 Windows 上起不来）；已配会话续接      |
| DSH（DeepSeek Harness） | CLI | 进程退出码 0（**未校验**）               | **未启用** | headless 模式不支持跨调用续跑，所以没配续接；指令含糊时会主动提问而无人应答，会 fail closed |

**「可调度」三条件**（缺一即报错，行上会挂「不可调度」徽标）：  
校验无错 ∧ 已启用 ∧ 配置完整（API = Key + 模型都非空；CLI = 命令非空）。

加自己的执行器：点 **「+ 添加模型」**（API 型：端点 / 模型 / Key 三个字段）  
或 **「+ 添加 CLI 执行器」**（命令 + 参数模板，参数里**必须**有 `{prompt}`）。  
改完点 **「保存」**，再点该行 **「探测」** 确认能被调度。

> **建议给 CLI 执行器配上世界门禁**（高级选项里的「世界门禁命令」，如 `test -f out.png`）。  
> 没有门禁的 `ProcessExitZero` 只能给出"未校验"的可信度——  
> 系统会照常播报，但它说的"已完成"其实只是"进程退出了"。  
> 任务历史里会把这类条目标成 **未校验**，一眼能看出来。

**CLI 执行器的「高级选项」**（默认收起）：

| 字段        | 作用                                   | 建议                                              |
| --------- | ------------------------------------ | ----------------------------------------------- |
| 单次执行超时（秒） | 0 / 留空 = 用默认 180 秒。**没有"不超时"档**      | CLI Agent 调到 **900**（15 分钟）或按需                  |
| 完成判定      | CLI 四选一；`async_task_poll` 标「不可用·未实现」 | 有权威串就用「日志权威串」                                   |
| 世界门禁命令    | 退出码 0 才算真完成                          | 能配就配                                            |
| 环境变量      | 每行 `KEY=VALUE`。**必须显式给 HOME**        | 不配 ⇒ 鉴权莫名失败                                     |
| 产物过滤      | 可选 glob，在时间窗命中的文件里再筛一层               | 留空 = 不筛；要筛写**相对工作目录**的路径（`out/*.png`、`**/*.md`） |
| 成功时自动打开产物 | 任务成功后自动打开                            | **默认开**；只在"成功 且 确实扫到文件"时动作                      |
| 会话续接      | 三格：id 在哪一行、哪个键、怎么带回去                 | codex 预置已配好；多轮对话靠它                              |

> **产物目录**（设置 → Agent 任务台 → 第 1 组）：产物落点 + `tasks/`（历史）+  
> `notice_assets/`（预合成语料）。留空 = `%APPDATA%\com.easyop.app\agent_desk_out`。

### 3.2 绑定槽位

**按键重映射 → 把某个键的「类型」设为「任务台」→ 选 S1…S4 → 选执行器。**

- 绑定方式目前**只有「指定执行器」可用**；  
  「按能力」「自动判定」在 UI 上标着**不可用**（路由未实现，Phase 4）——  
  选了派发会直接报错（刻意不置灰，否则老配置读不出来）。
- 绑定改完**立刻落盘**，不需要额外保存。
- 槽位与执行器是**多对一**：多个槽可以共用同一个执行器（但每个槽有自己独立的会话）。

### 3.3 发起任务：按键，或页面「派发到该槽」

**用按键：**

1. 按下绑定任务台的键，说话。**再按一次结束录音**（toggle，不是按住说话）。
2. 识别结果直接**进后台队列**。屏幕提示会告诉你"已开始执行（任务 #N）"或"已排队（前面还有 N 条）"。
3. 然后你就可以走开了。

**用页面：**

1. 打开 **任务台** 页面 → 「调试工具 → 手动派发」。
2. 选一个**已绑定且可调度**的槽位，写任务内容（**可以直接打字，不必走语音**）。
3. 点 **「派发到该槽（后台执行）」**。
4. 旁边还能：**新起一轮对话**（丢掉该槽会话 id，下一条新起话题）/  
   **清空待执行**（一键清积压，不影响正在执行的）。

**取消：**

- **取消执行**会终止这条任务的**整棵进程树**（`cmd.exe` 外壳 → `node.exe` 干活，  
  只杀外壳的话 node 会继续改文件、继续烧额度、攥着管道不放）。  
  入口有两个、动作同一个：运行中任务行右边的 `×`，以及「取消执行」按钮。
- 取消是"置标志 + 收尾"，不是瞬时动作，正常 **0.5 秒左右**停住  
  （按钮先变「取消中…」，真停下来才恢复）。
- **取消不产未读、不播报、不留结果文本**——它是干净的。
- 撤掉排队中的任务（`×`）不影响正在执行的那条。

**跑完之后，系统会主动做三件事：**

1. **语音播报结论**（PC 喇叭出声）——念的是这次任务的结论，不是一句干巴巴的"任务已完成"。
2. **有产物就自动打开**——只扫到 1 个文件直接打开；多个就打开所在文件夹并选中最新的。
3. **产生未读**（该槽灯转成**绿色待播**，亮度随未读数分三档）——按一下该槽的键，或到页面「播报 → 播报未读」，听完整结果。播报时该槽转**青色**。

> ⚠️ **自动打开只发生在"任务成功"那一刻。** 失败、超时、取消的任务**不扫产物**——  
> 那时目录里留下的是半成品，当"产物"打开是主动误导。想看那些任务的输出，用任务历史。

### 3.4 播报念什么：总结与播报设置

**设置 → Agent 任务台 → 「总结与播报」**：

| 设置          | 作用                                                         | 默认                |
| ----------- | ---------------------------------------------------------- | ----------------- |
| 总结用执行器      | **留空 = 不二次总结，直接念 Agent 自己的结论**（推荐）；非空 = 用那个执行器再跑一次压成更凝练的一句 | 空                 |
| 摘要字数上限      | 播报正文长度上限，生效时再取 `max(20, 本值)`                               | 180 字（可调 20–1500） |
| 总结提示词模板     | 占位符 `{task}` / `{output}` / `{max_chars}`；仅总结执行器非空时生效      | 内置模板              |
| 总结失败时退回截断原文 | 开 = 总结不出来就念原文截断；**宁可播一句粗糙的原文，也不要"灯亮了按下去没声音"**              | 开                 |
| 状态播报        | 开始 / 进度 / 完成 / 异常各播一句固定语料。**不产生未读**，关掉它不影响灯                | 开                 |
| 播报哪几类       | 四类单独开关（进度最吵，可单独关）                                          | 全开                |
| 去抖间隔（秒）     | **只约束进度类**；终态与"任务已开始"永不受约束；0 = 不限                          | 30                |
| 进度档位（分钟）    | 「已运行 N 分钟」固定档位，共 3 档；留空或 0 = 该档不用                          | 1 / 5 / 15 分钟     |

**为什么默认不总结**：CLI Agent 交回的**最后一句**本就是它给自己做的总结，  
再套一层模型不会更准，只会更慢、更容易跑偏。  
总结**不占槽位、不阻塞下一条任务**（后台另起一次调用）。

### 3.5 播报未读：完整链路与租约

**两条通道，别混**（这是整套灯语可信度的地基）：

| 通道               | 是什么              | 产未读吗        | 能被抢占吗    |
| ---------------- | ---------------- | ----------- | -------- |
| **状态播报**（Notice） | 开始/进度/完成/异常的固定语料 | **不产**      | 能被结果播放抢占 |
| **结果未读**（Result） | 任务终态的完整结论        | **产**（该槽灯亮） | 可接管任何东西  |

**听结果有两条路：**

1. **按键播放**（真机）：按一下该槽的键 ⇒ 系统取租约 → 合成 → 真的播 → 播完才回执；
2. **页面播报**（任务台 → 播报 → 播报未读）：选槽位 → 点「播报 S{n} 的未读」，  
   完整链路一样，回执由播放器自己给。

**租约规则**（页面「调试工具 → 播放租约」可模拟演练）：

- 取租约**不扣未读**，只有**回执（完整听完）**&#x624D;扣一条；
- **被抢占或半途断电，未读都留着**——"播了多少"不能变假账；
- 一条播放只消费一条未读；听完还有，再听一次；
- 「释放（抢占/中断）」归还不消费——`释放 ≠ 听完`。

**丢弃未读**（页面 → 播报 → 丢弃全部未读）：**两段式确认**，  
是不可撤销的人工出口——放弃收听、清掉积压。这些结果不会再被念出来（是**删除**，不是已读）。  
系统任何自动流程都不会丢未读。

**离线播报**：点「预合成全部语料」把 11 句固定语料提前合成好（缓存在产物目录的  
`notice_assets/`），**拔网线也能播状态**。列表里每句标注「已就绪 / 未预合成」，  
可单句「试听」。

### 3.6 产物发现：判据是「时间窗 + 可选 glob」

任务成功后，系统会在该执行器配的**工作目录**里找"这次任务动过的文件"：

- **时间窗**：只收 `mtime ≥ 任务开始时刻` 的文件。这是主判据。
- **glob**（可选）：在时间窗命中的文件里再按名字筛一层。
  - `*.md` —— 只命中工作目录根下的 markdown
  - `out/*.png` —— 命中 `out` 目录里的 png
  - `**/*.md` —— 命中任意深度的 markdown（`*` 不跨目录，要跨层写 `**`）
- **上限**：深度 4 层、最多 4000 个条目。超限**如实报告**（日志写明被截断），不假装扫完。
- **跳过**：`.git`、`node_modules`、`target`、`.venv`、`.cache` 等 17 类目录不进去扫，  
  **跳过了几个会写进日志**——"没扫到产物"的两种可能（真没有 / 全被跳过）你能区分。
- **没配工作目录 ⇒ 不扫盘**（绝不拿 easyop 自己的目录顶替）。

> **`out/` `build/` `dist/` 不在跳过名单里。** 当初把它们当"构建产物目录"排除，  
> 是拿别人的习惯替你做了决定——而大量工具恰恰把成果写进 `out/`。

### 3.7 任务历史：异步的前提

**任务台**页面 → 「任务历史」。列表显示**最近 50 条**（最新在前）：

- 槽位（S1–S4）、结果状态（已完成 / 失败 / 超时 / 已取消）
- 完成是否经**世界门禁校验**（未校验的挂 `未校验` 标签——  
  "进程结束了"不等于"事情做成了"）
- 你的**原话**、开始时间、跑了多久、用的哪个执行器、产物数量

**点一行展开**：原话 / 失败原因 / 续接的会话 id / 产物清单（绝对路径）/  
输出尾部 / 完整日志。

**磁盘上留 200 条**，位置在**产物目录下的 `tasks/`**：

```
<产物目录>/tasks/
  index.jsonl                          ← 一行一条记录（列表页读它）
  1758591234567_s1_t18.log             ← 任务 #18 的完整输出
```

超过 200 条从最老的开始删，**连它的 `.log` 一起删**（不会只删索引留下孤儿日志）。

> ⚠️ **历史是"跑了什么"的记录，不是"当前在跑什么"。** 队列和未读**刻意不持久化**——  
> 重启后队列为空（那些子进程已经不存在了，恢复一条"正在执行"是假象），  
> 但**未读会保留**（跨重启存活，拔电不丢）。

### 3.8 外部会话监工：给"你自己开终端跑 codex"补一句播报

你在**自己的终端**里跑 codex（不经过任务台），过程你看得见，但**你走开了没人告诉你跑完了**。

**外部会话监工**补的就是这个缺口：它盯着  
`%USERPROFILE%\.codex\sessions\**\rollout-*.jsonl`，看到一轮跑完就把结论接进通知层播报。

- 开关：**设置 → 任务台 → 外部会话监工**（出厂默认**开**；没装 codex 时零副作用）。
- 启动后**第一轮只登记偏移不播报**（否则历史会话会被当成新事件播一堆；  
  代价是启动前 1 秒跑完的会漏——**漏报远比误报好**）。
- 它**不产生未读**——只播一句固定语料（"任务已完成"），正文只上屏作字幕。

> **一句话区分**：任务台管"我说给它听的活"；外部会话监工管"我自己在终端里跑的活"。

## 4. 和「手动开终端 + 语音键输入 + 回车」到底差在哪

**"全程手动"指**：自己开终端 → 用语音键把话当普通文本上屏 → 自己读一遍 → 自己回车。

| 维度           | 全程手动（语音上屏）              | 任务台（按键 / 页面派发）            |
| ------------ | ----------------------- | ------------------------- |
| 命令由谁拼        | **你自己**（说错就上屏了错字）       | 系统按执行器的参数模板拼              |
| 拼装错误的风险      | 高（同音字、漏参数）              | 低（模板固定）                   |
| 多轮上下文        | 自己记住 / 手动加 `resume`     | ✅ 同一槽位自动续接                |
| 过程可见         | ✅ 全可见                   | ❌ **不可见**（唯一短板，历史兜底）      |
| 结果是否可靠送达     | ❌ 你得盯着                  | ✅ 播报 + 未读 + 灯             |
| "真的做成了吗"     | 你自己判断                   | ✅ 完成判定 + 可选世界门禁           |
| 超时 / 取消回收    | 你自己 Ctrl+C（还可能漏掉子进程）    | ✅ 超时自动 kill；取消**终止整棵进程树** |
| 排队 / 去重 / 取消 | 无                       | ✅ 有（同槽串行，深度上限 8，满员报错不丢）   |
| 同时跑多个        | 靠多开终端                   | ✅ 跨槽并行（4 槽）               |
| 离开电脑         | ❌ 等不到                   | ✅ 未读跨重启存活，历史在磁盘上          |
| **事后可追溯**    | 靠终端 scrollback（关了窗口就没了） | ✅ **完整输出独立落盘，留 200 条**    |
| 完成后自动开产物     | ❌                       | ✅                         |
| 拔网线还能被告知     | ❌                       | ✅（语料预合成后，状态播报离线可用）        |


### 代价（诚实说）

- **过程不可见**（进度输出被丢弃；完整输出跑完后进历史）；
- **失败不会自动重试**（唯一例外：会话续接疑似失效时丢 id 重跑一次）；
- **产物判据有原理性局限**（§6 末尾两条）。

## 5. 排错：常见报错与对策

| 报错 / 现象                            | 原因                                             | 对策                                                       |
| ---------------------------------- | ---------------------------------------------- | -------------------------------------------------------- |
| `槽位 S1 未绑定执行器`                     | 该槽没绑                                           | 按键重映射 → 类型=任务台 → 选执行器                                    |
| `槽位 S1 绑定的执行器 xxx 不存在`             | 执行器被删了                                         | 重新绑定（删除执行器会连带清空引用它的槽位）                                   |
| `…不可调度：未启用`                        | 执行器 `enabled = false`                          | 「模型配置 → ④ 执行器」打开开关                                       |
| `…不可调度：配置不完整`                      | API 缺 Key/模型，或 CLI 缺命令                         | 补齐字段                                                     |
| `…不可调度：<具体错误>`                     | 校验硬错误（如 CLI 参数缺 `{prompt}`）                    | 错误里会点名具体哪一条                                              |
| `S1 用的是「按能力」绑定，但能力路由尚未实现（Phase 4）` | 绑定方式选错                                         | 改成「指定执行器」                                                |
| `S1 没能派发：…（你的原话：…）`                | 派发被拒（未绑 / 不可调度 / 队列满 / 重复）                     | **失败绝不退回上屏**——原话只在提示里                                    |
| 任务 3 分钟被判超时                        | 用了默认 180 秒（照 HTTP 定的）                          | CLI 执行器超时调到 900000 毫秒                                    |
| 灯亮了但按下去没声音                         | 该槽没有未读结果文本                                     | 未读与播报是两套；确认任务真的完成（取消不产结果）                                |
| 「播报哪几类」标签看不清                       | ~~旧版配色~~ 已在 v0.41.13 修复（特异度覆盖）                 | 升级到 v0.41.13+                                            |
| 取消后任务好像还在跑                         | 取消是"置标志+收尾"，要起 taskkill + 结束行读                 | 正常 0.5 秒内停住；超 2 秒看日志：`runner 收尾超时` = 树没杀干净（会如实记日志）       |
| 取消后进程列表还有 `node.exe`               | 它可能在跑**别的槽位**的活儿                               | 取消只终止这一条任务的树                                             |
| 任务跑完了但没打开产物                        | ① 没配工作目录（不扫盘）② mtime 在时间窗外 ③ 被 glob 筛掉 ④ 任务未成功 | 看日志 `任务台产物：在 <目录> 扫到 N 个新文件…（共访问 N 个条目，跳过 N 个目录）`，四个数字定位 |
| 历史里没有刚跑完那条                         | 历史面板 10 秒刷新                                    | 等 10 秒或点「刷新」                                             |
| 完整日志是空的                            | 日志被清理（200 条上限）或当时写盘失败                          | **不代表任务失败**——任务已按列表状态结束                                  |
| 拔网线后状态播报没声                         | 语料未预合成                                         | 先点「预合成全部语料」，`all_cached` 才是离线可用判据                        |
| TTS 相关一切不播                         | API Key 没填                                     | 播报区会标「预合成不可用：TTS 未配置」；去「模型配置 → ③ 语音合成」                   |

## 6. ⚠️ 当前未实现的能力（已知边界）

写在这里是为了**避免你按着说明书去用不存在的东西**：

| 项目                       | 状态                                                           |
| ------------------------ | ------------------------------------------------------------ |
| **「按能力」/「自动判定」槽位绑定**     | ❌ 未实现（Phase 4）。选了派发直接报错；`Capability` 目前只用于显示候选               |
| **完成信号 `AsyncTaskPoll`** | ❌ 未实现，校验层直接拒绝保存这种配置                                          |
| **逐行执行日志（跑的过程中实时显示）**    | ❌ 没有。后台执行的进度输出仍被丢弃；**完整输出跑完后落进历史**                           |
| **失败自动重试**               | ❌ 没有（仅"续接失效"会降级重跑一次）                                         |
| **从历史面板"打开产物"**          | ❌ 没有。自动打开只在任务成功那一刻；后端也刻意没有"打开任意路径"的命令（不扩大攻击面）                |
| **`stderr` 单独落盘**        | ⚠️ **格式支持、实际为空**：`RunOutcome` 没有 stderr 字段。失败原因只在"原因"那一行且已截断 |
| **键盘喇叭出声**               | ❌ 未接 PCM 通道。当前从 **PC 喇叭**出声；页面播报链路验的是账本与租约层                  |

**已完成的硬件联动**（不在未实现清单里，但值得知道状态）：

| 项目 | 状态 |
| --- | --- |
| **开发板灯语（命令 `0x16`）** | ✅ **已完成并实机验证**（2026-10-14）：固件已烧，两侧已通，v2 语义（执行蓝 / 播放青 / 待播绿+三档亮度 / 空闲全灭 + S5 按键闪 120ms）表现与设计一致。唯一遗留约束是 **Windows HID 描述符缓存** —— 灯完全不响应时先让开发板重新枚举（关机再开机 / 拔插 USB），而不是先怀疑代码。详见 §2「灯语对照」下的提醒 |

**产物发现的两条固有局限**（不是 bug，是判据的性质）：

1. 任务期间**别的程序**写进同一目录的文件也会被算成产物（时间窗只认 mtime，  
   分不清是谁写的）。别拿有别的程序在写文件的目录当工作目录。
2. "没找到产物"和"任务没产出"在界面上长得一样。缓解：看日志里的扫描统计，  
   以及配 glob 收窄范围。

## 7. 快速上手清单（5 分钟）

```
1. 模型配置 → ④ 执行器：确认 Codex CLI 已「启用」，填好「工作目录」，
   点「探测」确认可调度。（工作目录必须填，否则产物发现不扫盘）
2. 按键重映射：给某个键设「类型 = 任务台」，选 S1，执行器选 Codex CLI
3. 任务台页面 → 调试工具 → 手动派发：选 S1，
   写「列出当前目录下最大的 5 个文件，并按大小排序」→ 派发
4. 等它跑完：听播报 → 看产物自动打开 → 槽位卡亮「未读」
5. 任务台 → 播报 → 播报未读：选 S1 听完整结果（回执后未读 -1）
6. 任务台 → 任务历史：展开刚跑完那条，看完整日志
7. （可选）设置 → Agent 任务台：确认总开关打开、
   「总结与播报」按需调整、外部会话监工开着
```
