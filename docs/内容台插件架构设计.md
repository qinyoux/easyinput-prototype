## 1. 插件集成与打开机制

### 1.1 插件发现与加载

easyop 启动时由 Rust 端 `plugin_registry::scan_dir` 扫描 `app_config_dir()/plugins/` 目录（只扫一层，不递归），读取每个子目录下的 `plugin.json` 清单文件，将声明的命令、页签注册到全局注册表。

**加载流程**：

```
easyop 启动 → plugin_registry::scan_dir()
  → 扫描 %APPDATA%/com.easyop.app/plugins/<id>/plugin.json
  → 解析 contributes.commands / contributes.pages
  → 注册到全局注册表（commands 表 + pages 表）
  → 前端通过 plugin_pages 命令获取页签列表
  → 侧边栏渲染页签按钮
```

**清单结构**（`plugin.json`）：

```json
{
  "id": "studio",
  "name": "内容台",
  "version": "0.4.0",
  "main": "index.js",
  "activationEvents": ["onPage:studio.board"],
  "contributes": {
    "commands": [
      { "id": "studio.state", "title": "内容台状态" },
      { "id": "studio.topics.save", "title": "保存选题" },
      { "id": "studio.quick_action", "title": "快捷动作（旋钮确认）" }
    ],
    "tools": [],
    "pages": [
      { "id": "studio.board", "title": "内容台", "icon": "board", "order": 50 }
    ]
  }
}
```

### 1.2 插件激活与命令注册

用户点击侧边栏「内容台」页签时，宿主触发激活流程：

```
用户点页签 → PluginPageContainer 组件
  → ensurePluginActivated("studio")
    → invoke("plugin_trigger_activate", { pluginId: "studio" })
      → Rust 端 emit "plugin:activate" 事件 { pluginId, code, dir }
        → 前端 pluginHost.ts 监听
          → 构造 eo.* API 对象
          → blob import 插件 index.js
          → 调用 mod.activate(context)
            → 插件注册命令：context.registerCommand(id, fn)
            → 插件注册页签：context.registerPage(pageId, renderFn)
          → 命令注册表存入 activatedPlugins Map
```

**eo.* 宿主 API 清单\*\*：

| API                           | Tauri 命令               | 功能                |
| ----------------------------- | ---------------------- | ----------------- |
| `eo.get_selection()`          | `eo_get_selection`     | 模拟 Ctrl+C 取前台应用选区 |
| `eo.clipboard_read()`         | `eo_clipboard_read`    | 直接读系统剪贴板          |
| `eo.replace_selection(text)`  | `eo_replace_selection` | 替换选区文本            |
| `eo.inject(text)`             | `eo_inject`            | 注入文本到光标处          |
| `eo.storage.get(key)`         | `eo_storage_get`       | 读插件存储             |
| `eo.storage.set(key, value)`  | `eo_storage_set`       | 写插件存储             |
| `eo.chat(messages, opts)`     | `eo_chat`              | LLM 对话            |
| `eo.run(program, args, opts)` | `eo_run`               | 子进程执行             |
| `eo.log.info/warn/error(msg)` | `eo_log_*`             | 日志                |

### 1.3 页签渲染与关闭

**渲染契约**（[docs/路径A-插件页签接口契约.md](./路径A-插件页签接口契约.md)，冻结）：

| 契约 | 内容                                           |
| -- | -------------------------------------------- |
| P1 | 渲染函数**同步**返回 `{refresh(), dispose()}` 生命周期对象 |
| P2 | 页签面板**禁用** `position:fixed`（会脱离宿主布局）         |
| P3 | **不得移动**宿主提供的容器元素                            |
| P4 | 样式**只作用于**本插件 class（`.studio-panel` 前缀）      |

**渲染流程**：

```
PluginPageContainer 拿到容器
  → getPluginPageRenderer("studio", "studio.board")(container)
    → renderPage(container)
      → buildView(container)：构造 DOM + 注入 <style> 到 document.head
      → refreshPanel()：异步加载台账数据 → 渲染选题列表 + 详情卡片
      → 返回 { refresh, dispose }
```

**关闭流程**：

```
用户切走页签 → PluginPageContainer unmount
  → lifecycle.dispose()
    → destroyPage("studio.board")
      → disposeView(view)：移 DOM + 移 <style>
```

### 1.4 插件部署

内置插件源在 `plugins/builtin/studio/`，运行时需拷贝到 `%APPDATA%/com.easyop.app/plugins/studio/`：

```bash
npm run plugins:deploy -- studio    # 部署
npm run plugins:list                # 查看部署清单
```

**部署后需重启 easyop**，发现层在启动时扫描插件目录。

## 2. 插件按键映射设计

### 2.1 设计概述

内容台插件通过**保留 UUID 桥接**机制接入 easyop 的硬件按键系统。插件不直接处理硬件事件，而是借 `host_action:<uuid>` 通道让固件回传触发信号，主机端拦截后路由到插件命令。

### 2.2 旋钮交互逻辑

采用**选中→确认两步模式**（与浮窗工作台 `workbench_prev/next/confirm` 同构）：

| 旋钮方向 | 动作类型               | 子动作       | 行为                               |
| ---- | ------------------ | --------- | -------------------------------- |
| 左旋   | 内容台（`Studio` kind） | `prev`    | 焦点移到上一个功能，emit `studio-focus` 事件 |
| 右旋   | 内容台（`Studio` kind） | `next`    | 焦点移到下一个功能，emit `studio-focus` 事件 |
| 按下   | 内容台（`Studio` kind） | `confirm` | 执行当前高亮功能，emit `studio-action` 事件 |

> v0.38.0 起，内容台旋钮独立成 `Studio` kind（与 `TaskDesk` 同级），
>
> 不再混在"功能动作"（`Named` kind）里。按键映射下拉里"内容台"是独立选项。

**功能列表**（5 项循环导航）：

| 焦点索引 | 动作 ID             | 中文标签 | 对应插件命令                         |
| ---- | ----------------- | ---- | ------------------------------ |
| 0    | `studio_new`      | 新建选题 | 从选区/剪贴板建选题                     |
| 1    | `studio_pipeline` | 一条龙  | `studio.gen.all`               |
| 2    | `studio_advance`  | 推进阶段 | `studio.stage.advance`         |
| 3    | `studio_export`   | 导出   | `studio.export`                |
| 4    | `studio_wechat`   | +公众号 | `studio.export`（publishWechat） |

### 2.3 保留 UUID 映射表

| UUID    | 常量名                   | Studio kind value | 用途    |
| ------- | --------------------- | ----------------- | ----- |
| `…000e` | `UUID_STUDIO_PREV`    | `prev`            | 焦点上一项 |
| `…000f` | `UUID_STUDIO_NEXT`    | `next`            | 焦点下一项 |
| `…0010` | `UUID_STUDIO_CONFIRM` | `confirm`         | 确认执行  |

> UUID 段 `00000000-0000-4000-8000-0000000000XX`，`01`–`0d` 已被方案切换/浮窗/命令面板/任务台/终端占用，`0e`–`10` 分配给内容台。

### 2.4 事件分发与处理链路

```
旋钮旋转 → 固件回传 host_action:<UUID>
  → host_action.rs::handle_host_action
    → 识别 studio UUID
    → prev: STUDIO_FOCUS = (focus + 4) % 5
    → next: STUDIO_FOCUS = (focus + 1) % 5
    → emit "studio-focus" { index, label }
    → 前端 App.tsx 监听 → notify("内容台 → 一条龙")

旋钮按下 → 固件回传 host_action:<UUID>
  → host_action.rs::handle_host_action
    → 识别 UUID_STUDIO_CONFIRM
    → action = STUDIO_ACTION_IDS[STUDIO_FOCUS]
    → emit "studio-action" { action, label }
    → 前端 App.tsx 监听
      → ensurePluginActivated("studio")
      → invokePluginCommand("studio", "studio.quick_action", { action })
        → cmdQuickAction 路由到对应功能
```

### 2.5 焦点状态管理

焦点索引存储在 Rust 端 `host_action.rs` 的 `static STUDIO_FOCUS: AtomicU8`，特点：

- **线程安全**：`AtomicU8` 无锁原子操作，HID 监听线程读写不阻塞
- **进程生命周期内持久**：不随页签切换重置
- **循环导航**：`(focus + 1) % 5` 和 `(focus + 4) % 5` 实现 5 项循环

### 2.6 快捷动作命令

`studio.quick_action` 是旋钮确认的统一入口，内部按 `action` 参数路由：

```javascript
async function cmdQuickAction({ action } = {}) {
  switch (action) {
    case 'studio_new':     // get_selection → fallback clipboard_read → topics.save
    case 'studio_pipeline': // loadMeta → gen.all
    case 'studio_advance':  // loadMeta → stage.advance
    case 'studio_export':   // loadMeta → export
    case 'studio_wechat':   // loadMeta → export { publishWechat: true }
  }
}
```

### 2.7 配置方式

在 easyop 按键映射配置页面，将旋钮三个方向分别绑定：

- 左旋 → 动作类型选「内容台」→ 子动作选"上一项（左旋切换焦点）"（`prev`）
- 右旋 → 动作类型选「内容台」→ 子动作选"下一项（右旋切换焦点）"（`next`）
- 按下 → 动作类型选「内容台」→ 子动作选"确认（按下执行）"（`confirm`）

「内容台」在动作类型下拉里是独立选项（与"任务台"同级），不在"功能动作"里。

配置后点「下发到开发板」即可。

## 3. UI 深浅色主题兼容设计

### 3.1 平台主题机制

easyop 使用 `<html data-theme="dark|light">` data 属性切换主题，由 `src/theme.ts` 驱动：

- **三模式**：`dark` / `light` / `system`（跟随操作系统）
- **持久化**：`localStorage["easyop.theme"]`
- **防闪烁**：`index.html` 内联脚本在首屏渲染前写入 `data-theme`
- **切换入口**：顶栏 `ThemeToggle.tsx` + 设置页 `GeneralSettings.tsx`
- **主题变量**：`src/styles.css` 定义 `--panel` / `--text` / `--border` / `--accent` 等

### 3.2 插件双主题适配方案

插件在 `.studio-panel` 上定义**插件私有 CSS 变量**，深色为默认值，浅色通过 `[data-theme="light"]` 覆盖：

```css
/* 深色（默认） */
.studio-panel {
  --sp-bg: linear-gradient(135deg, #0d0f1a, #141829, #0f1220);
  --sp-text: #e8eaf2;
  --sp-ac1: #a78bfa;  /* 紫色强调 */
  --sp-ac2: #60a5fa;  /* 蓝色强调 */
  --sp-card-bg: linear-gradient(135deg, rgba(22,28,46,.6), rgba(18,22,38,.4));
  /* ... 30+ 变量 */
}

/* 浅色覆盖 */
[data-theme="light"] .studio-panel {
  --sp-bg: linear-gradient(135deg, #f8faff, #f0f4ff, #fafbfd);
  --sp-text: #1c1917;
  --sp-ac1: #7c3aed;
  --sp-ac2: #2563eb;
  --sp-card-bg: linear-gradient(135deg, rgba(255,255,255,.8), rgba(248,250,255,.6));
  /* ... 同名变量浅色值 */
}

/* 子元素全部引用 var(--sp-xxx) */
.studio-panel .sp-card {
  background: var(--sp-card-bg);
  border: 1px solid var(--sp-card-bd);
  color: var(--sp-text);
}
```

### 3.3 主题变量对照表（摘录）

| 变量             | 深色值                    | 浅色值                   | 用途   |
| -------------- | ---------------------- | --------------------- | ---- |
| `--sp-bg`      | 深蓝渐变                   | 淡蓝白渐变                 | 面板背景 |
| `--sp-text`    | `#e8eaf2`              | `#1c1917`             | 主文字  |
| `--sp-ac1`     | `#a78bfa`              | `#7c3aed`             | 紫色强调 |
| `--sp-ac2`     | `#60a5fa`              | `#2563eb`             | 蓝色强调 |
| `--sp-card-bd` | `rgba(96,165,250,.15)` | `rgba(96,165,250,.2)` | 卡片边框 |
| `--sp-err`     | `#fb7185`              | `#dc2626`             | 错误色  |
| `--sp-ok`      | `#34d399`              | `#15803d`             | 成功色  |

### 3.4 星空主题适配

深色模式下 `::before` 伪元素用 `radial-gradient` 点缀白色星点（`opacity: .4`）；浅色模式下星点改为淡蓝色（`opacity: .18`），保持视觉一致性而不刺眼。

### 3.5 兼容性测试策略

| 验证项              | 方法                                        |
| ---------------- | ----------------------------------------- |
| 深色模式             | 切换到 `dark` → 面板背景深蓝渐变 + 白色星点 + 紫蓝发光卡片     |
| 浅色模式             | 切换到 `light` → 面板背景淡蓝白渐变 + 淡蓝星点 + 白底淡紫蓝边框  |
| 切换不闪             | 切换主题时无白屏闪烁                                |
| 样式隔离             | 插件样式不泄漏到平台（harness 检查 `.studio-panel` 前缀） |
| 无 position:fixed | 页签面板不脱离宿主布局（harness 正则检查）                 |

## 5. 使用说明设计

### 5.1 安装步骤

1. **部署插件**：`npm run plugins:deploy -- studio`
2. **重启 easyop**：发现层在启动时扫描插件目录
3. **验证**：侧边栏出现「内容台」按钮 → 点击打开面板

### 5.2 界面操作指引

面板打开后，点右上角「?」按钮可随时查看内置使用说明。

**六阶段流程**：

```
灵感 → 情报卡 → 正文 → 去AI味 → 配图 → 已导出
```

每个阶段有**准入校验**：进「正文」要情报卡 ≥3 条；进「去AI味」要有正文。缺前置会报错，**不静默跳过**。

**操作流程**：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 新建选题 | 输入框填标题（或留空自动取选中文本/剪贴板），点「＋ 新建选题」 |
| 2 | 一条龙（推荐） | 点「一条龙」按钮，自动跑 情报卡→标题→正文→去AI味 |
| 3 | 分步操作 | 逐个点「生成情报卡」「生成标题」「生成正文」「去 AI 味」 |
| 4 | 选定标题 | 在「标题候选」卡片里点选一个标题 |
| 5 | 字数设置 | 动作区「字数」输入框设置正文目标字数（默认 500） |
| 6 | 导出 | 「导出」组稿+校验 / 「+小红书包」/ 「+公众号」 |
| 7 | 推进阶段 | 手动推进到下一阶段（带准入校验） |
| 8 | 自检 | 检查 Python / pub.py / 自带脚本是否就位 |
| 9 | 删除 | 删除当前选题 |

**一条龙断点续跑**：中途某步失败后，重试会**跳过已落库的步骤**，只补跑未完成的。

### 5.3 旋钮操作指引

**配置**：在按键映射配置中，将旋钮三方向绑定：

| 旋钮方向 | 绑定动作 |
|----------|---------|
| 左旋 | 内容台 · 上一项 |
| 右旋 | 内容台 · 下一项 |
| 按下 | 内容台 · 确认 |

**使用**：
1. 旋转旋钮 → 界面提示当前选中的功能名（如"内容台 → 一条龙"）
2. 按下旋钮 → 执行当前高亮功能

**功能列表**（5 项循环）：新建选题 → 一条龙 → 推进阶段 → 导出 → +公众号

### 5.4 常见问题解答（FAQ）

| 问题 | 原因 | 解决 |
|------|------|------|
| 点「新建选题」提示"没有选中文本" | `eo.get_selection` 模拟 Ctrl+C 时 easyop 已在前台 | 先在外部应用中 `Ctrl+C` 复制，再点「新建选题」（自动从剪贴板取） |
| 正文生成超时 | LLM 耗时超过默认 15s | 在「模型配置」页调大超时（建议 30s+） |
| +小红书包失败 | `pub.py pack xhs` 需配图，当前无生图能力 | 手动配图后重试，或先只做「导出」 |
| +公众号提示"手动粘贴" | 公众号登录态失效 | 按提示找到本地 HTML 文件，手动粘贴到公众号编辑器 |
| 浅色主题下面板仍是深色 | 旧版插件 CSS 硬编码 | 更新到最新版插件（v0.4.0+ 支持双主题） |
| 旋钮操作无反应 | 固件白名单不认新 UUID | 需同步更新固件白名单（`…000e`-`…0010`） |
