> **版本** v1.0 · 2026-09-19 · 状态：定案>

> **互补文档** 《easyop 扩展机制规范》——架构设计与安全模型；《内容台规范》——内置插件实例>

## 一、插件架构设计

### 1.1 整体架构：三层分离

```
┌─ 发现层 plugin_registry.rs ──────────────────────────────┐
│  启动时扫 app_config_dir()/plugins/<id>/plugin.json       │
│  解析 → 校验 → 内存注册表（static Mutex）                  │
│  对外：search_hits() 供 ⌘SS 搜索 / find_loaded() 供激活    │
└──────────────────────────────────────────────────────────┘
                          ↓ 命令被触发
┌─ 激活层 plugin_host.rs + pluginHost.ts ───────────────────┐
│  Rust: 读 index.js → emit("plugin:activate", {code, ...}) │
│  前端: listen → 定义 eo.* → blob import(code) →           │
│        activate(context) → exec(commandId)                │
└──────────────────────────────────────────────────────────┘
                          ↓ 调用宿主能力
┌─ 能力层 eo.* Tauri commands ──────────────────────────────┐
│  eo_get_selection / eo_replace_selection / eo_inject      │
│  eo_storage_get / eo_storage_set / eo_log_*               │
│  eo_chat / eo_run                                         │
└──────────────────────────────────────────────────────────┘
```

| 层                | 职责                            | 代码位置                                                 | 状态 |
| ---------------- | ----------------------------- | ---------------------------------------------------- | -- |
| **发现层**          | 扫目录、读清单、校验、检索                 | `src-tauri/src/plugin_registry.rs`                   | ✅  |
| **激活层**          | 读入口代码、推给前端、执行 activate        | `src-tauri/src/plugin_host.rs` + `src/pluginHost.ts` | ✅  |
| **能力层**          | 7 个 `eo.*` Tauri commands     | `src-tauri/src/plugin_host.rs`                       | ✅  |
| **接入层 · ⌘SS 搜索** | 插件命令进搜索结果                     | `src-tauri/src/ss_palette.rs`                        | ✅  |
| **接入层 · 按键配置**   | `contributes.keyActions` 绑物理键 | —                                                    | ⬜  |
| **沙箱**           | capability 强制隔离               | —                                                    | ⬜  |

### 1.2 插件清单 `plugin.json`

对标 VSCode `package.json.contributes`：

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明",
  "main": "index.js",
  "activationEvents": [
    "onCommand:my.action",
    "onKeyword:关键词",
    "onKey:KEY8",
    "onSelection"
  ],
  "contributes": {
    "commands": [
      {
        "id": "my.action",
        "title": "执行动作",
        "keywords": ["执行", "run", "zhixing"]
      }
    ],
    "tools": [
      {
        "command": "my.action",
        "subtitle": "副标题",
        "keywords": ["工具关键词"]
      }
    ]
  },
  "capabilities": ["storage", "selected-text", "llm", "inject", "log", "runner"]
}
```

### 字段说明

| 字段                     | 必需 | 说明                               |
| ---------------------- | -- | -------------------------------- |
| `id`                   | ✅  | 全局唯一，建议与目录名一致                    |
| `name`                 | ✅  | 展示名                              |
| `main`                 | ✅  | 入口文件，**相对路径**（禁止 `..` 与绝对路径）     |
| `version`              | —  | 版本号                              |
| `description`          | —  | 一句话说明                            |
| `activationEvents`     | —  | 激活时机。**当前只收录，不消费**——懒激活由命令触发驱动   |
| `contributes.commands` | —  | 命令声明：`id` / `title` / `keywords` |
| `contributes.tools`    | —  | 把命令挂进 ⌘SS 内置工具区                  |
| `capabilities`         | —  | 声明需要的能力。**当前无法强制隔离**，仅作文档约束      |

### 搜索可见性规则

- 声明了 `tools` → **只有被 `tools` 引用的命令**进 ⌘SS 搜索
- 没声明 `tools` → 全部命令都可搜到（按 `title` + `keywords`）

### 命名空间铁律

`<id>.<action>` 的 `<id>` 必须全局唯一。两个插件都叫 `studio.*` 会导致  
`find_plugin_by_command` 只认第一个命中的，搜索会指错插件。

### 1.3 插件入口 `index.js`

ESM 单文件，自包含（blob import 后不能再 import 相对路径文件）：

```javascript
export function activate(context) {
  const eo = context.api;

  context.registerCommand('my.action', async () => {
    const text = await eo.get_selection();
    const result = await eo.chat(
      [{ role: 'user', content: `处理：${text}` }],
      { temperature: 0.3 }
    );
    await eo.replace_selection(result);
    eo.log.info('完成');
  });
}

export function deactivate() {
  // 清理资源
}
```

### `context` 对象

| 属性                                | 类型         | 说明                             |
| --------------------------------- | ---------- | ------------------------------ |
| `context.api`                     | `eo`       | 宿主能力 API，见 §三                  |
| `context.pluginId`                | `string`   | 当前插件 id                        |
| `context.pluginDir`               | `string`   | 插件目录绝对路径（定位自带脚本用）              |
| `context.registerCommand(id, fn)` | `function` | 声明命令实现（id 须与 `plugin.json` 一致） |

### 1.4 生命周期

| 阶段      | 时机                           | 行为                                                               |
| ------- | ---------------------------- | ---------------------------------------------------------------- |
| **发现**  | easyop 启动 / `plugins_rescan` | 扫目录、读 `plugin.json`、校验、进内存注册表                                    |
| **懒激活** | 命令首次被触发                      | `emit("plugin:activate")` → 前端 blob import → `activate(context)` |
| **执行**  | 每次命令触发                       | 已激活则直接调注册的 fn；未激活先走激活                                            |
| **停用**  | easyop 退出 / 插件移除             | 调 `deactivate()`（当前未实现主动调用）                                      |

> **懒激活**：未激活时命令仍出现在搜索结果中（从 `plugin.json` 静态读取），执行时才加载 `index.js`。

### 1.5 校验规则（加载期即挡，不留到执行期）

坏插件**不会拖垮其他插件**：加载失败只记一条 warn 并跳过。校验项：

- `id` / `name` / `main` 非空
- `main` 不越界（无 `..` / 无绝对路径）
- 入口文件存在
- 命令 id 非空且不重复
- `tools` 不得引用未声明的命令
- 清单 ≤ 256KB

## 二、通信机制

### 2.1 当前实现：Tauri Commands（进程内 invoke）

插件 JS 运行在主窗浏览器上下文，通过 `@tauri-apps/api/core` 的 `invoke()` 调用  
Rust 侧 `#[tauri::command]`：

```
插件 JS  ──invoke("eo_chat", {messages, opts})──→  Rust 命令  ──→  LlmClient
     ←────────── JSON 返回 ──────────────────────────
```

| 优点                      | 缺点                 |
| ----------------------- | ------------------ |
| 零网络开销（进程内消息）            | 插件必须运行在 easyop 进程内 |
| 类型安全（Rust 端 serde 反序列化） | 无法被外部进程调用          |
| 无需鉴权                    | —                  |
| 天然跨语言（JS ↔ Rust）        | —                  |

**适用**：所有内嵌插件（当前唯一已实现的方式）

### 2.2 规划：HTTP 桥（阶段 3，面向外部应用）

| 项  | 设计                                       |
| -- | ---------------------------------------- |
| 协议 | HTTP/JSON，`127.0.0.1` 仅本机                |
| 端口 | 启动时动态分配，写 `app_config_dir()/bridge.port` |
| 鉴权 | 随机 token，写 `bridge.token`                |
| 实现 | 裸 `tokio::TcpListener`                   |

### 端点（对齐 Capability Core）

| 端点            | 方法       | 作用                            |
| ------------- | -------- | ----------------------------- |
| `/health`     | GET      | 探活 + 能力清单                     |
| `/inject`     | POST     | 注入文本到光标处                      |
| `/llm`        | POST     | LLM 补全（继承已配置 Key，**不暴露 Key**） |
| `/llm/stream` | POST     | SSE 流式 LLM                    |
| `/selected`   | GET      | 读取选中文本                        |
| `/replace`    | POST     | 替换选中文本                        |
| `/clipboard`  | GET/POST | 剪贴板读写                         |
| `/reveal`     | POST     | 打开目录                          |
| `/action`     | POST     | 派发白名单具名动作                     |

> **不提供** `/profile/switch` `/key/trigger`——桥只暴露宿主能力，不暴露业务动作。

`bridged` kind 小程序启动时注入环境变量 `EASYOP_BRIDGE_URL` / `EASYOP_BRIDGE_TOKEN`，  
外部应用读环境变量即可调桥，easyop 不在则降级独立运行。

### 2.3 通信方式对比

| 方式                   | 延迟      | 隔离  | 复杂度 | easyop 适用场景     |
| -------------------- | ------- | --- | --- | --------------- |
| **Tauri invoke**（当前） | ~0.1ms  | 无   | 低   | 内嵌插件 ✅          |
| **HTTP 桥**（规划）       | ~1ms    | 进程级 | 中   | 外部应用            |
| WebSocket            | ~1ms    | 进程级 | 中高  | 需要双向推送（如流式 LLM） |
| gRPC                 | ~0.5ms  | 进程级 | 高   | 重计算服务（过重，不推荐）   |
| 共享内存                 | ~0.01ms | 无   | 高   | 极低延迟场景（过重，不推荐）  |
| MCP（远期）              | ~1ms    | 进程级 | 中   | 接入外部 MCP server |

> **结论**：内嵌插件用 Tauri invoke（已实现），外部应用用 HTTP 桥（阶段 3），>   
> 远期可接 MCP server。不引入 WebSocket / gRPC / 共享内存——对 easyop 的场景过重。

## 三、宿主 API（`eo.*`）

### 3.1 可用 API

| API                           | 对应 Tauri 命令            | 状态 | 说明                              |
| ----------------------------- | ---------------------- | -- | ------------------------------- |
| `eo.get_selection()`          | `eo_get_selection`     | ✅  | 读选中文本                           |
| `eo.replace_selection(text)`  | `eo_replace_selection` | ✅  | 替换选中文本                          |
| `eo.inject(text)`             | `eo_inject`            | ✅  | 注入光标处                           |
| `eo.storage.get(key)`         | `eo_storage_get`       | ✅  | 读插件存储（返回 `null` 表示不存在）          |
| `eo.storage.set(key, value)`  | `eo_storage_set`       | ✅  | 写插件存储（原子写，每插件独立 `storage.json`） |
| `eo.log.info(msg)`            | `eo_log_info`          | ✅  | 日志 info                         |
| `eo.log.warn(msg)`            | `eo_log_warn`          | ✅  | 日志 warn                         |
| `eo.log.error(msg)`           | `eo_log_error`         | ✅  | 日志 error                        |
| `eo.chat(messages, opts)`     | `eo_chat`              | ✅  | LLM 补全（非流式）                     |
| `eo.run(program, args, opts)` | `eo_run`               | ✅  | 子进程执行                           |

### 3.2 `eo.chat` 参数

```typescript
// messages
[{ role: "user", content: "你好" }, ...]

// opts（可选）
{
  system: "系统提示词",       // 默认 undefined
  temperature: 0.3,           // 默认由全局配置决定
  max_tokens: 1000,           // 默认由全局配置决定
  clean: true                 // 是否清洗输出，默认 true
}

// 返回：string（LLM 补全文本）
```

### 3.3 `eo.run` 参数

```typescript
eo.run(program: string, args?: string[], opts?: {
  timeoutSecs?: number,   // 超时秒数
  cwd?: string,           // 工作目录
})

// 返回
{
  exit_code: number,
  stdout: string,
  stderr: string,
  timed_out: boolean,
  cancelled: boolean
}
```

### 3.4 尚未实现的 API

| API                                     | 影响            | 现状替代                           |
| --------------------------------------- | ------------- | ------------------------------ |
| `eo.chat_stream`                        | 拿不到流式增量       | `eo.chat` 一次性返回                |
| `eo.panel.open`                         | 开不了独立窗口       | 主窗内 DOM 浮层                     |

| `eo.config`                             | 读不到 easyop 配置 | 只能硬编码路径                        |

## 四、集成步骤：从零开发一个插件

### Step 1：创建目录结构

```
plugins/builtin/my-plugin/
├── plugin.json     # 清单
├── index.js        # 入口（自包含 ESM 单文件）
└── test/           # 可选：验证台
    └── harness.mjs
```

### Step 2：编写 `plugin.json`

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "main": "index.js",
  "contributes": {
    "commands": [
      { "id": "my.run", "title": "运行", "keywords": ["执行", "run"] }
    ]
  },
  "capabilities": ["storage", "llm"]
}
```

### Step 3：编写 `index.js`

```javascript
export function activate(context) {
  const eo = context.api;

  context.registerCommand('my.run', async () => {
    const input = await eo.get_selection();
    const result = await eo.chat(
      [{ role: 'user', content: `处理：${input}` }],
      { temperature: 0.3 }
    );
    await eo.replace_selection(result);
    eo.log.info('完成');
  });
}

export function deactivate() {}
```

### Step 4：部署到运行目录

```bash
npm run plugins:deploy -- my-plugin   # 拷到 %APPDATA%\com.easyop.app\plugins\
```

> 内置插件源在 `plugins/builtin/<id>/`，运行时读的是 `app_config_dir()/plugins/<id>/`。>   
> 中间差一次拷贝，用 `npm run plugins:deploy` 跨过去。

### Step 5：验证

```bash
npm run plugins:test                  # 如果有验证台
# 重启 easyop
# ⌘SS 搜"运行" → 回车 → 确认执行
```

### Step 6：（可选）调试

| 手段                         | 用法                                                       |
| -------------------------- | -------------------------------------------------------- |
| **日志面板**                   | easyop 主窗 → 日志面板，搜 `[plugin]` 前缀条目                       |
| **`storage.json`**         | 直接看 `%APPDATA%\com.easyop.app\plugins\<id>\storage.json` |
| **`plugins:list`**         | `npm run plugins:list` 干跑列出将部署的插件                        |
| **`plugins:deploy --dry`** | 只演练不写盘                                                   |
| **Tauri devtools**         | `npm run tauri dev` 时 F12 开 devtools                     |

### 命令速查

```bash
npm run plugins:list         # 干跑：列出将被部署的插件
npm run plugins:deploy       # 把 plugins/builtin/* 拷到运行目录
npm run plugins:deploy -- my-plugin   # 只部署某个
npm run plugins:deploy -- --dry       # 只演练
npm run plugins:test         # 跑插件验证台
```

## 五、实际应用考量

### 5.1 版本兼容性

- `plugin.json` 有 `version` 字段，但**当前无兼容性检查**——easyop 不校验插件版本是否匹配宿主 API 版本
- **建议**：插件作者在 `capabilities` 里声明所需能力，宿主在激活前检查能力是否全部可用，缺失则报明确错误而非运行时崩溃
- **breaking change 风险**：`eo.*` API 签名变更属于 `major` 版本。当前 `eo.*` 尚未标版本，第一个外部插件出现时应冻结 API 并加版本号

### 5.2 错误处理

| 层      | 策略                                                                                    | 代码位置                              |
| ------ | ------------------------------------------------------------------------------------- | --------------------------------- |
| 发现层    | 坏插件**不拖垮其他插件**：加载失败只记 warn 并跳过                                                        | `plugin_registry.rs` scan_dir     |
| 校验     | `id`/`name`/`main` 非空 · `main` 不越界 · 入口存在 · 命令 id 不重复 · `tools` 不引用未声明命令 · 清单 ≤ 256KB | `plugin_registry.rs` validate     |
| 激活层    | `activate()` 抛异常 → 记 error 日志 → 标记激活失败，不影响其他插件                                        | `pluginHost.ts` runPlugin catch   |
| 命令执行   | 命令 fn 抛异常 → 记 error 日志 → 返回 null                                                      | `pluginHost.ts` execCommand catch |
| 宿主 API | 每个 `eo_*` Tauri command 返回 `Result<T, String>`，错误信息传回 JS                              | `plugin_host.rs`                  |


### 5.3 性能影响

| 环节 | 开销 | 评估 |
|------|------|------|
| 启动扫描 | 读 N 个 `plugin.json`（≤ 256KB 每个） | 可忽略（实测 2 插件 < 1ms） |
| 懒激活 | 首次触发时 blob import + `activate()` | ~10-50ms（JS 解析 + 执行），仅一次 |
| 命令执行 | 已激活后直接调注册的 fn | 零开销，纯 JS 函数调用 |
| `eo.*` invoke | Tauri IPC（进程内消息） | ~0.1ms/次 |
| `eo.chat` | 调 LLM API | 网络延迟主导，宿主开销可忽略 |
| `eo.run` | spawn 子进程 | 进程创建 ~50ms，由调用方控制 |

> **blob import 的代价**：激活时将整个 `index.js` 读入内存建 Blob URL 再 `import()`。
> 大插件（> 1MB）会有一次性解析延迟。建议入口文件控制在 100KB 以内。

### 5.4 安全隔离

**当前状态：无沙箱**

| 配置项 | 值 | 位置 |
|--------|---|---|
| `withGlobalTauri` | `true` | `tauri.conf.json` |
| CSP | `null` | `tauri.conf.json` |
| 自定义命令进 ACL | 否（89 个命令命中 0 次） | `gen/schemas/acl-manifests.json` |

**风险**：

| 风险 | 影响 |
|------|------|
| 插件读 LLM API Key | `invoke('get_api_key')` 可读 |
| 插件调任意 Tauri 命令 | 无 ACL 拦截，可调 `push_config` / `quit_app` 等 |
| 插件写任意文件 | `eo.run` 可执行任意程序 |
| 插件间隔离 | 无，可访问 `window.__plugins` 里其他插件的命令表 |

**一期妥协**：内置插件（随 easyop 发布）作者就是 easyop 自己，信任边界内。
**外部插件需先做 4 项安全改造**：

1. 为自定义命令定义权限（`src-tauri/permissions/`，按能力分组）
2. 插件窗口配独立 capability，只放行必要项
3. 不开 `withGlobalTauri`
4. 全局 CSP 从 `null` 变成实际策略

> 在出现第一个真正的外部插件需求前不做沙箱（代价与收益不匹配）。
> `capabilities` 字段保留为文档约束 + 代码层 best-effort 过滤。

### 5.5 调试与监控

| 手段 | 用法 |
|------|------|
| **日志面板** | easyop 主窗 → 日志面板，`eo.log.*` 输出带 `[plugin]` 前缀 |
| **`storage.json`** | 直接看 `%APPDATA%\com.easyop.app\plugins\<id>\storage.json` 确认插件状态 |
| **`plugins:list`** | `npm run plugins:list` 干跑列出将部署的插件 |
| **`plugins:deploy --dry`** | 只演练不写盘，确认部署目标 |
| **验证台** | 仿内容台 `test/harness.mjs`，`npm run plugins:test` |
| **Tauri devtools** | `npm run tauri dev` 时 F12 开 devtools，断点插件的 blob 模块 |
| **性能 profiling** | `getPluginStats()` 返回各插件的 activate 耗时 / 命令调用次数与累计耗时 / `eo.*` API 调用次数。超 5s 的操作自动记 warn 日志（`[plugin-profile]` 前缀） |

## 六、完整示例：灵感速记插件

> 源码：`plugins/builtin/demo-quick-note/`

### `plugin.json`

```json
{
  "id": "demo-quick-note",
  "name": "灵感速记（示范）",
  "version": "0.2.0",
  "main": "index.js",
  "activationEvents": ["onCommand:demo.quick_note", "onKeyword:灵感"],
  "contributes": {
    "commands": [
      {
        "id": "demo.quick_note",
        "title": "记一条灵感",
        "keywords": ["灵感", "速记", "note", "inbox", "linggan", "sj"]
      }
    ],
    "tools": [
      {
        "command": "demo.quick_note",
        "subtitle": "记下一句话，稍后整理",
        "keywords": ["灵感", "速记", "note", "inbox", "linggan"]
      }
    ]
  },
  "capabilities": ["storage", "selected-text", "log"]
}
```

### `index.js`

```javascript
const KEY = 'inbox';

export function activate(context) {
  const eo = context.api;

  context.registerCommand('demo.quick_note', async () => {
    let seed = '';
    try {
      seed = await eo.get_selection();
    } catch (_) {
      seed = '';
    }

    const notes = (await eo.storage.get(KEY)) || [];
    const item = { text: (seed || '').trim(), at: Date.now() };
    notes.push(item);
    await eo.storage.set(KEY, notes);

    await eo.log.info(`灵感速记：已保存 ${notes.length} 条`);
    return { count: notes.length, item };
  });
}

export function deactivate() {}
```

## 七、与现有机制的关系

| 现有机制 | 插件如何接 |
|---------|-----------|
| `BUILTIN_TOOLS` | 变成内置插件的 `contributes.tools` |
| `MINI_APP_RENDERERS` | 变成插件的 `contributes.panels`（未实现） |
| `host_action` 保留 UUID | 插件 `contributes.keyActions` 映射到保留 UUID 段（未实现） |
| `NAMED_ACTIONS` | 第一期不动态化；内容台 6 个动作走静态登记 |
| `ss_palette` 搜索 | 合并 `plugin_registry::search_hits()` ✅ |
| MCP server（远期） | easyop 作为 MCP client，把 MCP tools 映射为插件 commands |

## 八、落地路线图

| 阶段 | 内容 | 状态 |

| **阶段 0** · 框架级前置 | LLM 泛化 + 执行器 + 能力内核 | ✅ |
