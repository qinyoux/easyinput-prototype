# 内容台规范

> **版本** v1.0 · 2026-09-18 · 状态：定案
> **定位** easyop 进程内的内容生产工作台（选题 → 情报卡 → AI 填充 → 配图 → 导出 → 发布）
> **形态** `component`（进程内组件窗口），非独立应用、非插件——是 easyop 长出来的器官
> **本文合并原《内容台集成方案》《内容台组件规范》两份文档**

---

## 一、定案（一句话）

**内容台是 easyop 的一个内置插件，不是独立应用，也不是编译进 easyop 的 component。**

它有自己的窗口（可独立开合、置顶、多屏移动），随 easyop 发布（放 `plugins/builtin/studio/`），通过 `eo.*` API 继承 easyop 的 LLM/ASR/按键方案/应用库。

> 为什么是插件而非 component：**不做沙箱时两者运行时权限相同，但插件路线把后端逻辑推到 JS，改 UI 不编译 Rust**。详见《easyop 扩展机制规范》§六.3 / §九。
>
> 判断口诀：**要"活在 easyop 里、共享它的能力"，就是插件或组件；要"独立于 easyop 存在"，才需要独立 APP。**

## 二、与 easyop 的关系

### 2.1 继承什么（选型的全部理由）

| 继承项 | eo.* API | 说明 |
|--------|----------|------|
| **LLM 配置** | `eo.chat` / `eo.chat_stream` | 复用已配置通道，**不再问 API Key** |
| **ASR 配置** | （二期）`eo.asr` | 语音口述选题/要求 |
| **按键方案库** | `eo.dispatch_action` | 物理键驱动看板 |
| **本机应用库** | `eo.reveal` | 导出后一键打开产物目录 |
| **文本注入** | `eo.inject` | **生成完直接注入光标处**——插件独有 |
| **选中文本读写** | `eo.get_selection` / `eo.replace_selection` | 选中素材 → 直接送进内容台当灵感 |
| **本地文件搜索** | （需扩展）`eo.search` | 快速定位历史稿件与导出包 |
| **统一日志** | `eo.log` | 进度与诊断进同一个日志面板 |
| **子进程执行** | `eo.run` | 调 `pub.py` / `gen_figs.py` / `qa_check.py` |
| **本地存储** | `eo.storage` | 台账（topics.json / runs.json） |
| **Host Action 通道** | `contributes.keyActions` | 物理键直驱看板（保留 UUID 段） |

### 2.2 不拥有什么（边界）

| 不拥有 | 归属 |
|--------|------|
| LLM/ASR 配置的**写入权** | easyop 设置页（组件只读；需改时引导跳转） |
| 按键映射的**下发权** | easyop 主链路（组件只消费 `host_action` 事件） |
| 固件协议 / HID 设备 | easyop（组件不碰 `transport`/`device`） |
| 独立启动入口 | 没有——不能双击启动，必须由 easyop 唤起 |

**关键约束：配置只有一份，且只有 easyop 能改。** 插件通过 `eo.*` 只读消费配置；需改时引导跳转 easyop 设置页。

### 2.3 为什么"独立进程"走不通

1. `profiles` 的内存副本才是唯一真源，磁盘只是快照——独立进程读写 `profiles.json` 会丢更新（last-write-wins）
2. 改键盘配置要下发固件（HID 句柄在 easyop 进程内）——独立进程没有 HID 句柄
3. `text_delivery` / `clipboard_util` / `everything` / `log_buffer`——独立进程一个都拿不到

> 插件路线走同进程，上述全部通过 `eo.*` API 拿到——这是选插件而非独立 APP 的原因。

## 四、入口与窗口契约

### 4.1 四条入口

| # | 入口 | 触发 | 落点 |
|---|------|------|------|
| ① | ⌘SS 面板搜索 | 输入「内容台」「选题」 | `plugin.json` 的 `contributes.tools` 声明；plugin_host 激活 |
| ② | ⌘SS 图标区 | 面板空闲时点图标 | `mini_apps` kind `"plugin"`，target = `"studio"` |
| ③ | 物理键 / 旋钮 | 按键触发 `host_action:<保留UUID>` | `contributes.keyActions` 映射到保留 UUID 段 `…0009` |
| ④ | 主窗页签 | 点侧栏「内容台」 | `Sidebar.tsx` 加一项（id `studio`，显示名「内容台」） |

> **命名避让**：`Sidebar.tsx:9` 已有 `id:"workbench"`（动作磁贴筛选）。新页签 id 用 `studio`、显示名用「内容台」。

### 4.2 窗口契约

| 项 | 值 | 理由 |
|---|---|------|
| label | `studio` | 与 UUID、命令前缀一致 |
| 尺寸 | 1080×720，可缩放 | 看板需横向空间（主窗 780 宽不够） |
| 装饰 | `decorations(true)` | 工作窗口需标题栏托移动；**与浮窗不同** |
| 置顶 | `always_on_top(false)` | 写稿要跟编辑器并排 |
| 任务栏 | 显示 | 常用工作窗口 |
| 单实例 | toggle | 避免多窗口并发写同一份台账 |

### 4.3 插件命令（`contributes.commands`）

| 命令 id | 作用 |
|---------|------|
| `studio.toggle` | 开合窗口（幂等） |
| `studio.state` | 取当前状态（选题/阶段/任务队列/配置就绪） |
| `studio.topics.list` / `studio.topics.save` / `studio.topics.remove` | 台账增删改（`eo.storage`） |
| `studio.stage.advance` | 推进阶段（六阶段流转，走确认门） |
| `studio.gen.title` / `studio.gen.body` / `studio.gen.humanize` / `studio.gen.figures` | 生成类（`eo.chat_stream`，进队列） |
| `studio.export` | 导出本地成品包（`eo.run`） |
| `studio.task.cancel` | 取消当前任务 |

**统一返回信封**：`{ ok, code, data, message }`（`capability::ApiEnvelope`），`SELECTOR_DRIFT` 单列一码。

### 4.4 事件契约

| 事件 | 载荷 | 用途 |
|------|------|------|
| `studio:progress` | `{ task_id, phase, percent, line }` | 进度推送（插件内 `postMessage`） |
| `studio:state-changed` | `{ topics_version }` | 台账变更广播 |

**必须带 `task_id`**——前端据此丢弃过期任务进度。**落盘契约**：改内存 → 校验 → 先落盘、后广播。

## 五、UI 代码组织

插件目录结构（随 easyop 发布，不参与 Tauri 编译）：

```
plugins/builtin/studio/
  ├── plugin.json             ← 清单（contributes.commands / keyActions / tools）
  ├── index.js                ← activate 入口（注册命令 → 绑定 eo.* 调用）
  ├── app/
  │   ├── StudioApp.tsx       ← 根组件
  │   ├── StudioBoard.tsx     ← 六阶段看板
  │   ├── TopicCard.tsx / TopicEditor.tsx
  │   ├── StudioRun.tsx       ← 任务进度 + 历史
  │   └── ...                 ← model.ts / store.ts / gen.ts 等
  └── dist/                   ← 构建产物（easyop 发版时预构建）
```

**开发效率**：改 `app/` 下 JS/TS 只需刷新 webview，不编译 Rust。改 `eo.*` 实现才需编译（一次性投资）。

## 六、本地数据层（JSON）

```
%APPDATA%\com.easyop.app\studio\
├── topics.json      # 选题台账（含 stage / intel / 平台映射）
├── runs.json        # 运行记录（环形裁剪）
└── publish.json     # 二期：草稿映射
```

工程约定：`eo.storage` 提供 KV 读写（每插件独立 `storage.json`）；台账序列化为 JSON 存入。`schema_version` 字段做版本迁移。将来换 SQLite 只改 `eo.storage` 实现。

## 七、七项功能路径

| # | 功能 | 数据流 | 失败表现 |
|---|------|--------|---------|
| 1 | 灵感收集 | 来源选择 → 采集器 → `Vec<Inspiration>` → 一键转选题 | 平台检索失败明确提示并跳过 |
| 2 | 情报卡 | 表单 → `intel.rs` 校验 → 写 `Topic.intel` | 凑不满 3 条角度 → 提示退回灵感采集 |
| 3 | 正文 AI 填充 | 选题 + 情报卡 → `prompts` → `llm_client::chat` → 950 字正文 | Key 未配 → 报"请先在设置里填 LLM" |
| 4 | 去 AI 味 | 正文 → humanizer 提示词 → 四层自检 | L4 不过 → 只重写受影响段落 |
| 5 | 配图生成 | 叠字（Python 通道）或 AI 生图（原生 HTTP）→ `qa_check` | 按 item 报错不中断整批 |
| 6 | 文章排版 | `文章.md` → 内联样式 HTML → 交付包 | 导出失败保留源稿 |
| 7 | 台账 | 本地 JSON（权威）→ 可选平台回写 | 无票 → 跳过并注明 |

## 九、执行器（runner）

通过 `eo.run`（`runner::run_stream`）调子进程，自动注入 UTF-8 环境。动作白名单：

| 动作 | argv | 期 |
|------|------|---|
| 校验稿件 | `pub.py check <post>` | 一期 |
| 排版导出 | `pub.py export --post <post> --out <dir>` | 一期 |
| 叠字配图 | `gen_figs.py --spec <spec.json>` | 一期 |
| AI 生图 | Rust 原生 `studio/imagegen.rs` | 一期 |
| 结构自检 | `qa_check.py <png…>` | 一期 |
| **发公众号草稿** | `pub.py publish wechat --save-draft` | **二期** |

工程约束：管道 UTF-8（`PYTHONIOENCODING=utf-8`）、不阻塞事件循环（`spawn_blocking`）、失败不静默、单并发（二期 Edge profile 互斥）。

## 十、二期：公众号回补（核心价值 = 自动配图上传）

### 10.1 为什么值得做

手动配图 7 张约 7~14 分钟；自动 `upload_body_image()` 逐张上传 + 插到光标处。**最慢最机械的一环恰好是自动化覆盖最完整的。**

### 10.2 一期必须预留

| 预留 | 做法 |
|------|------|
| 接口位 | `studio/publish.rs` 定义 `Publisher` trait，一期不实现 |
| `publish.json` | 台账留 `appmsgid` / 封面 URL 字段 |
| 前置代码 | `cp/wechat.py` / `login-wechat.bat` / `profiles/` / `pub.py publish` 原样不动 |

### 10.3 二期约束

1. 登录态会过期——发布前 `pub.py status` 预检，未登录置 `blocked`
2. 平台改版选择器失效——提示重跑 `probe`，**不自动重试**
3. 单并发——Edge profile 互斥

## 十二、验证策略

1. **单元**：`store` 六阶段流转 + 原子写；runner 超时/取消/非零码/UTF-8；`intel` 边界
2. **契约（可进回归）**：每个 Python 动作跑 `--help` 校验参数名；交付包结构断言（`图/` 顺序 == 正文 `![]()` 顺序）
3. **E2E（人工）**：一篇真稿走完全流程；HTML 逐字目视；实际粘贴进公众号后台确认排版不塌

---

## 十三、回滚策略

- **纯增量**：不动固件协议、不动 `payload` 既有分支、不动 `host_action` 既有分流。回滚 = 移除 `plugins/builtin/studio/` + 新 UUID + 页签
- **数据面**：只新增 `plugins/builtin/studio/` 目录（可删），不碰 `config.json`/`profiles.json`/`apps.json`
- **熔断**：`plugin.json` 不存在时 plugin_registry 自然跳过
- **二期独立性**：一期完全不依赖二期

## 十六、适用场景

| 场景 | 适合？ |
|------|--------|
| 在 easyop 里写稿，全程不切应用 | ✅ 独立窗口与编辑器并排，配置全继承 |
| 边写边用物理键 | ✅ `contributes.keyActions` 映射保留 UUID，固件零改动 |
| 生成完直接注入光标处 | ✅ `eo.inject` 插件独有 |
| 选中素材 → 送进内容台 | ✅ `eo.get_selection` 直接接住 |
| 口述选题 | ✅ 继承 ASR 配置（二期 `eo.asr`） |
| 改 UI 不编译 Rust | ✅ 纯 JS 插件，刷新 webview 即生效 |
| 无人值守批处理 | ❌ 需 easyop 常驻 → 走独立 CLI |
| 手机 / 异地 | ❌ 绑死本机进程 → 走网页桥 |
