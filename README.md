# easyop —— 语音输入 + EasyInput 开发板按键配置

> 一款面向 ESP32-S3 可编程键盘开发板的 Windows 桌面应用，
> 让「哑键盘」变成会说话、会编辑、会切换方案的 AI 输入工具。

## 项目简介

easyop 是 [第七期 AI 硬件训练营](https://example.com) 第 2 课的作业项目，基于 **Tauri 2 + React + Rust** 构建。它将一块 EasyInput V2.0 开发板（ESP32-S3）连接到 Windows 主机，实现以下能力：

| 能力 | 说明 |
|------|------|
| **按键配置** | 可视化编辑 8 个按键 + 编码器的动作映射，一键下发到开发板 |
| **语音输入** | 按一下 PTT 键开始说话（**短按，不是按住**），流式识别实时出字幕；再按一下**注入输入框（不发送）**，或录音期间直接按**回车 = 注入并发送** |
| **语音编辑** | 选中文本 → 按编辑键 → 说出修改要求 → LLM 自动编辑 → 替换原文 |
| **方案切换** | 按键触发方案切换，主机端接管切换逻辑并重新下发 |
| **提示词库** | KEY4 浮窗随方案切换的提示词清单，可直接增删改，选中回车即上屏 |
| **固定文本** | 按键一键注入预设文本，支持中文（剪贴板 + Ctrl+V） |
| **打开应用** | 按键一键拉起本机应用（程序 / 文件 / 网址 / 文件夹） |
| **启动终端** | 按键开（或复用）终端并把命令打进输入框**不回车**，再由语音把内容接上去 |

### 技术栈

- **前端**：React + Vite + TypeScript
- **后端**：Rust + Tauri 2（Win32 FFI：HID / 键盘钩子 / SendInput / ShellExecuteW）
- **语音识别**：火山引擎流式 ASR（WebSocket WSS）
- **LLM 编辑**：OpenAI 兼容 API（火山引擎豆包 / OpenAI / Anthropic / Ollama / 自定义）
- **开发板**：EasyInput V2.0（VID `0x303A` / PID `0x1006`，固件协议 `ai_keyboard.v1`）

## 功能特性

### 1. 按键映射

可视化 4×2 按键网格 + 圆形编码器，每个输入可配置为：

| 动作类型 | 示例 | 说明 |
|----------|------|------|
| 禁用 | — | 该按键无功能 |
| 功能动作 | `copy` / `paste` / `toggle_profile` | 预定义命名动作 |
| 组合键 | `Ctrl+Alt+A` | 模拟键盘快捷键 |
| 输入文本 | `你好世界` | 一键注入固定文本（支持中文） |
| 打开应用 | `host_action:<uuid>` | 按键触发时拉起本机应用 |

支持多方案库：创建 / 编辑 / 删除 / 切换方案，每个方案独立保存按键映射。

### 2. 语音输入

- **单次按键（Hold）**：**按一下开始说话**（短按即可，不是按住说话）→ 说完有**两种**收尾方式：
  - **再按一下 PTT 键** ⇒ 识别文本**注入输入框**，之后由你手动编辑或提交（**不回车**）
  - **直接按回车**（录音期间）⇒ **注入 + 发送一步完成**，省掉一次按键
  - 面板上也会出现红色的失败条（仅当注入失败时），可「重新注入」或「丢弃」
- **连续通话（Call）**：按一次开始，说完一句自动上屏，再按一次结束
- **实时字幕**：后台浮层在录音过程中持续显示识别文字；识别结束即隐去
- **麦克风来源**：自动 / 电脑 / Wi-Fi / 蓝牙（⚠️ 开发板无蓝牙音频通路，选「蓝牙」不生效）

### 3. 语音编辑

选中文本后按 `Ctrl+Shift+E`：

1. 浮层显示「正在听修改要求…」
2. 说出修改要求（如「把第二段删掉」）
3. 再按 `Ctrl+Shift+E` 确认
4. LLM 根据原文 + 修改要求生成编辑后的文本
5. 自动替换选中的原文

支持流式输出：LLM 编辑过程实时显示在浮层上。

### 4. 方案切换

在按键上绑定「切换方案」「上一个方案」「下一个方案」功能动作，按下时：

1. 固件回发 Host Action 报文到主机
2. 主机切换激活方案
3. 自动下发新方案到固件
4. 前端 UI 同步更新

### 5. 固定文本（支持中文）

按键绑定含中文的固定文本（如「你好」）时：

- 纯 ASCII 文本 → 走固件原生 `{"text": ...}` 通道
- 含中文文本 → 主机端用剪贴板 + Ctrl+V 注入，兼容所有应用

### 6. 提示词库（KEY4 提示词库浮窗）

按 KEY4（或主窗口「工作台」页顶栏的 **「提示词库」** 按钮）唤出的浮窗是一本**跟着方案走**的
提示词册子 —— 你给每个方案存一批常用的提示词（写邮件、写周报、让 AI 干活的指令……），
需要时唤出、选中、回车，文本直接注入到光标处。
两个入口等价：硬件 KEY4 适合在工作流中随手唤出；顶栏按钮用于**没有开发板时的界面验证**。

| 操作 | 方式 |
|------|------|
| 切换方案 | 浮窗内容自动换成该方案的提示词，不用手动指定 |
| 选择 | 鼠标点击，或 `↑` / `↓` 移动高亮 |
| 上屏 | 选中后按 `回车` —— 提示词注入到光标处 |
| 新增 | 点顶栏「**＋ 新增**」，在行内输入框里写完回车 |
| 编辑 | 点该行的「**编辑**」，行内改成输入框，回车保存 |
| 删除 | 点该行的「**删除**」 |
| 取消 / 收起 | 输入态下 `Esc` 先取消编辑；非输入态 `Esc` 收起浮窗（easyop 继续后台运行） |

- 提示词存在**方案**里（写入 `profiles.json`），随方案一起导出与备份
- 每条正文上限 4096 字节，每个方案上限 60 条
- 浮窗尺寸固定，条目多时列表内部滚动

## 快速开始

### 前置依赖

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | ≥ 18 | 前端构建 |
| Rust 工具链 | stable | 后端编译 |
| MSVC 构建工具 | — | Tauri Windows 编译硬依赖 |
| EasyInput V2.0 固件 | `ai_keyboard.v1` | 开发板已烧录 |

### 安装 MSVC 构建工具（如未安装）

1. 下载 [Build Tools for Visual Studio](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
2. 运行安装器，勾选「**使用 C++ 的桌面开发**」
3. 安装完成后重开终端，验证 `link.exe /?` 可识别

### 开发运行

```bash
# 安装依赖
npm install

# 启动开发模式（前端热更新 + 后端自动重编译）
npm run tauri dev
```

### 构建发布版

```bash
npm run tauri build
# 产物：src-tauri/target/release/*.exe
```

### 验证环境

```bash
npm run build                  # 前端 + TypeScript 类型检查
cd src-tauri && cargo check    # Rust 编译检查
cd src-tauri && cargo test     # 单元测试（19 项）
```

## 使用教程

### 第一步：配置语音识别

1. 打开 easyop，点击「**语音设置**」页签
2. 填写火山引擎 ASR 配置：
   - **API Key**：在[火山引擎控制台](https://console.volcengine.com/speech)获取
   - **ASR URL**：`wss://openspeech.bytedance.com/api/v2/asr`
   - **Resource ID**：`volc.bigasr.sauc.duration`
3. 点击「**测试连接**」验证

### 第二步：配置 LLM 编辑（可选）

在「语音设置」页签的 LLM 配置区域：

1. 选择后端类型（火山引擎豆包 / OpenAI / Anthropic / Ollama / 自定义）
2. 填写 Endpoint、Model、API Key
3. 点击「**测试连接**」验证
4. 设置编辑快捷键（默认 `Ctrl+Shift+E`）

### 第三步：配置按键映射

1. 点击「**按键映射**」页签
2. 在侧栏选择一个方案（或点击「新建」创建新方案）
3. 点击要配置的按键（KEY1-KEY8 或编码器）
4. 在右侧面板选择动作类型：
   - **功能动作**：从下拉列表选择（复制、粘贴、切换方案等）
   - **组合键**：输入快捷键（如 `Ctrl+C`）
   - **输入文本**：输入要注入的文本（支持中文）
   - **打开应用**：从应用库选择已添加的应用
5. 点击顶部「**下发到开发板**」按钮

### 第四步：配置本机应用（可选）

1. 点击「**本机应用**」页签
2. 点击「**从开始菜单添加**」自动枚举本机应用
3. 或手动添加：填写名称、目标路径（程序 / 文件 / 网址 / 文件夹）
4. 点击「**测试打开**」验证
5. 回到「按键映射」页签，将按键动作设为「打开应用」并选择刚添加的应用
6. 下发到开发板

### 第五步：使用语音输入

**单次按键模式（短按开始 / 两种收尾）**：
1. 确保光标在目标输入框中
2. **按一下 PTT 键开始录音**（短按，不用按住），浮层实时显示识别字幕
3. 说完之后，二选一结束：
   - **再按一下 PTT 键** ⇒ 识别文本进输入框，**但不会回车**，接着由你手动编辑或提交
   - **直接按回车** ⇒ 文本注入输入框 **并** 回车发送，一步到位（适合"说完就想直接执行/发送"的场景）
4. 用第二种方式（再按 PTT 键）时，要提交按 **KEY2**（默认绑 Return）

> ⚠️ 面板上那个 ● 按钮与 PTT 键**完全等价**（都是"按一下开始、再按一下交付"），
> 不会出现"按钮写着『开始录音』、按下去却在做别的事"这种情况。

> ⚠️ 设置 → 语音 里的「粘贴后自动回车」**只管其他注入路径（固定文本 / 提示词 / 提示词浮窗），
> 不影响语音输入**：语音输入的回车与否由上面第 3 步你按了什么决定。
> 为什么不一律自动回车？因为回车是不可撤销的提交，而语音内容常常是接在一条还没看完的命令后面的。

**连续通话模式**：
1. 按 PTT 键一次开始录音
2. 说完一句自动上屏，继续说下一句
3. 再按 PTT 键一次结束

### 第六步：使用语音编辑

1. 在任意应用中**选中要编辑的文本**
2. 按 `Ctrl+Shift+E`，浮层显示「正在听修改要求…」
3. **说出修改要求**（如「把这段改得更正式一点」）
4. 再按 `Ctrl+Shift+E` 确认
5. LLM 编辑结果实时显示在浮层上
6. 编辑完成后自动替换选中的文本

### 第七步：使用方案切换

1. 创建多个方案（如「办公方案」「游戏方案」）
2. 在某个按键上绑定「**切换方案**」功能动作
3. 下发到开发板
4. 按下该按键，自动切换到下一个方案并下发

### 第八步：使用提示词库（KEY4 提示词库浮窗）

1. 两种呼出方式任选：主窗口「工作台」页顶栏点 **「提示词库」**（无开发板时用来验证），
   或按硬件 KEY4
2. 浮窗内容是**当前方案**的提示词（随方案自动切换）
3. 点顶栏「**＋ 新增**」，在行内输入框里写下提示词，回车保存
4. 用 `↑` / `↓` 选中一条，按 `回车` —— 提示词注入到光标处
5. 需要修改就点该行的「**编辑**」，想删就点「**删除**」
6. 切换到别的方案再唤出，浮窗里就是那个方案自己的提示词

### 第九步：使用 ⌘SS 命令面板

按 `Ctrl/Cmd + K`（或点顶栏按钮）唤出面板，直接输入关键词搜索本机应用、应用库、系统命令与内置工具。

- **小程序图标区**：面板空闲时（还没输入关键词），**搜索框正下方**会摊开已集成的小程序图标，
  鼠标移上去显示名称，**点一下即启动**；一开始打字图标区就整块收起，不干扰搜索
- **搜索**：支持中文、全拼（`weixin`）、简拼（`wx`）与单词缩写（`vscode`）；
  `↑↓` 选择、`回车` 执行、`Esc` 只收起面板（easyop 继续在后台运行）
- **内置工具**：输入「计算器」「待办」「截图」「翻译」进入，
  面板主体切换成工具界面，`Esc` 退回搜索结果（不会启动任何外部程序）
- **`=` 前缀算数**：直接输入 `= 12*34` 出结果

### 第十步：把外部应用集成为「小程序」

「小程序」= 你把**外部**的 App / Web 项目 / 项目目录登记进 easyop，之后在面板里点一下就能启动它。

1. 唤出面板，输入「小程序」或「集成」，回车进入集成管理页
2. 在上方表单里选择类型：
   - **外部应用**：填 exe 路径（如 `C:\Tools\notepad++.exe`），可另填启动参数
   - **Web 项目**：填网址（如 `my-app.vercel.app`，缺协议会自动补 `https://`）
   - **项目目录**：填本地目录（如 `D:\code\my-app`）
3. 填目标时会自动给出本机应用建议，点一下即可填入；名字留空会自动推导
4. 点「集成」，回到搜索即会出现这一项 —— 回车或点击就真的启动它；
   同时它也会出现在面板空闲时的**图标区**里，之后不用打字、点一下就能开

> 与「内置工具」的区别：内置工具是 easyop 自带的一小块界面，进入后只换面板视图；
> 小程序是你自己的外部目标，点一下会收起面板并把外部程序 / 网页 / 目录打开，
> 效果等同于在资源管理器里双击它。

### 第十一步：使用「启动终端」（按键开终端 + 语音补内容）

把「启动环境」和「输入内容」拆成两个独立步骤，适合 `codex` 这类要**长命令 + 一句中文**的场景。

1. **先配一次**：设置 → **终端启动** → 填「要预置的命令（前缀）」，例如
   `codex exec --skip-git-repo-check`；需要的话填工作目录、选终端程序；点**保存**。
   旁边有「**试一下（立刻启动终端）**」，配错了不用去板子上按就能发现。
2. **给某个键绑上「启动终端」**：工作台 → 按键配置 → 动作类型选「功能动作」→ 值选「启动终端」。
3. **用**：按一下那个键 → 弹出终端窗口，输入框里已经有你配的命令（**没有回车**）
   → 再按语音键说话（例如"打开计算器"）→ 识别到的内容接在命令后面 → 回车执行。

几点要知道的：

- **中间的空格是程序补的**。命令末尾本来没有空格，语音文字也不带前导空格，
  少了这一下就会粘成 `--skip-xxx打开计算器`（被当成一个参数），报错却像"codex 参数写错了"。
- **焦点已经在一个终端上时不会开新窗口**，直接往那个终端里打。所以窗口没拿到焦点时，
  点一下那个终端、再按一次键就能接上 —— **不要连按**，那只会开出多个窗口。
- 「打完直接回车执行」**默认关**，建议保持关：命令是前缀，回车等于把它当一条完整命令跑掉。

## 三通道通信架构

| 通道 | 协议 | 方向 | 用途 |
|------|------|------|------|
| **HID** | USB/BLE HID Feature Report 0x10/0x11 | 双向 | 按键配置下发 + Host Action 回执 |
| **Wi-Fi UDP** | EIAU/EIHB/EICC/EICA（端口 17333） | 双向 | 16kHz PCM 音频流 + 心跳 + 流控 |
| **云端 ASR** | WebSocket WSS | APP→云端 | 火山引擎流式语音识别 |

- **EIHB 心跳**：开发板每 2 秒广播，APP 据此判定在线（5 秒超时）
- **EIAU v2 音频**：32 字节头 + PCM 负载，20ms/帧
- **EICC 控制**：APP 发送 start/stop/keepalive，开发板回 EICA 确认
- **麦克风来源**：自动（优先键盘 Wi-Fi，回退电脑）/ 电脑 / Wi-Fi / 蓝牙
  （⚠️ 蓝牙**不生效**：开发板只有 Wi-Fi UDP 一条音频通路，`bluetooth` 会被纠错迁移为 `auto`）

## 主链路说明

| 链路环节 | 位置 |
|----------|------|
| 按键方案下发 | `commands.rs` → `payload::to_firmware_json` → `transport::send_config` |
| 配置回执解析 | `payload::parse_ack`（0x11 kind 0x03） |
| Host Action 分发 | `host_action.rs`（0x11 kind 0x05）→ 方案切换 / 文本注入 / 打开应用 |
| 语音 PTT 触发 | `ptt_hook.rs` → `session.rs` → `asr.rs` → `text_delivery.rs` |
| 语音编辑 | `session.rs` → `asr.rs`（Hold 模式）→ `voice_edit.rs` → `llm_client.rs` |
| 键盘 Wi-Fi 音频 | `keyboard_audio.rs` → `ei_protocol.rs` |
| 麦克风源选择 | `session.rs` MicSource → `start_hold`/`start_call` |
| 提示词库增删改 | `workbench.html` → `commands.rs` `mutate_prompts` → `profiles.json` + `workbench::publish_board_input` |
| 提示词上屏 | `workbench.html` `workbench_commit` → `workbench.rs` `commit_selected` → `text_delivery` |
| 面板小程序图标区 | `ss_palette.html` `refreshMiniApps` → `mini_apps_list` → `mini_apps::launch` → `launcher` |
| HID 集合过滤 | `device.rs` `has_feature_report()` → `host_action.rs` `try_open_all` |

## 已知限制

- 仅支持 **Windows**（Win32 HID / 键盘钩子 / SendInput 均为 Windows 专有）
- 语音注入复用剪贴板 + 模拟 Ctrl+V，会短暂占用剪贴板（约 1.2s）
- 开发板按键配置依赖固件协议 `ai_keyboard.v1`（VID `0x303A` / PID `0x1006`）
- 固件**没有蓝牙音频通路**，而且**不是"还没做"，是芯片层面就不通**：ESP32-S3 的蓝牙是 **BLE-only**（Espressif 官方：`Classic Bluetooth is not supported`），而所有成品"蓝牙麦克风/耳机"走的是 **HFP/HSP（经典蓝牙）** ⇒ 这条路在 SoC 上就不存在；LE Audio 也不行（ESP-IDF 支持表里 ESP32-S3 的 `ESP-BLE-ISO` / `ESP-BLE-AUDIO` 均为不支持）。固件侧同样只有一条音频通路：`AudioTransport` 枚举只有 `Unavailable` / `WifiUdp`（音频常量 `wifi_udp`）。
  所以这台设备上**蓝牙只传按键事件（HID），不传音频**；要板载麦克风就只能是 **Wi-Fi UDP**。麦克风来源里的「蓝牙键盘麦克风」因此**不生效**（配置里写了 `bluetooth` 会被纠错迁移为 `auto`）。
- 蓝牙（BLE HID）在固件里是**常开**的，**没有开关**，按键事件同时经 USB 与蓝牙发出；配对由 Windows 侧完成。easyop **不参与**蓝牙配对，也**读不到**蓝牙连接状态（开发板只在 BLE GATT 特征上发布 `{"ble":{...}}`，不走 USB HID 的 `0x11` 回执；宿主未实现 BLE 读取）。此前界面上的「启用蓝牙」开关与「配对」按钮下发的 `{"cmd":"ble_enable"}` 固件并不认识（配置协议只接受固定字段，没有指令字段），已改为如实报错。
- 固件不支持多方案，方案切换由主机端接管（借 Host Action 通道回传）
- 固件 USB HID 原生 text 通道仅支持 ASCII；含非 ASCII（中文等）的固定文本由主机端自动改道剪贴板 + Ctrl+V 注入，完整支持汉字

## 开发协作

本项目由**多个 AI 编码助手并行修改同一个工作树**，因此「改完代码」的定义里包含版本收尾。
完整公约见 [AGENTS.md](AGENTS.md)，核心三条：

1. **升版本**：`npm run version:bump -- patch|minor|major`
   —— 版本号唯一真源是 `package.json` 的 `version`，`tauri.conf.json` / `Cargo.toml` /
   `package-lock.json` 由 `npm run version:sync` 同步，**不要手改**（历史上已漂移过一次）
2. **写说明**：`CHANGELOG.md` 记开发者视角的「新增 / 变更 / 修复 / ⚠️ 未完成」，
   `README.md` §版本历史 记用户视角摘要 —— 两处都必须有本版条目
3. **自检**：`npm run version:check` 必须通过（退出码 0）

> 判断版本档位的一句话：**老用户的配置与固件能否直接升级上来？**
> 能 → `minor` / `patch`；不能（改了固件 UUID 映射、配置格式、命令签名）→ `major`。

```bash
npm run version:check          # 校验四处版本号 + 变更说明齐备性
npm run version:bump -- minor  # 升版本 + 同步 + 插入 CHANGELOG/README 骨架
```
