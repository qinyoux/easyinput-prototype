因此本文对 UI 的所有要求，都围绕两个常驻元素：① 当前参数的中文描述（不是数字，不是色块）；② 底部常驻的「下一次按下会发生什么」动作提示条。

## 1. 产品目标（3 条）

1. **把「AI 生图」从一次性的对话框，变成一台可调的机器。**
   用户不是在写 prompt，而是在拧旋钮：选风格 → 调强度 → 出图，整个过程可回退、可重来、可对比。
   成功标准：用户在不输入任何英文 prompt 的前提下，完成一次满意的风格化出图。

2. **零配置可用。**
   打开页签、拖一张图、按一次键就能出图。API Key 复用 easyop 已有的 `llm_api_key`（火山方舟），
   用户不需要注册任何新账号、不需要填任何表单。
   成功标准：新用户从「打开页签」到「看到第一张生成图」的操作次数 ≤ 5 次。

3. **调参过程中的每一步都可解释、失败时每一句话都可执行。**
   不给「操作失败」这种空话；给「生成失败：方舟返回 ModelNotOpen，去控制台开通 Seedream 模型」这种能照着做的句子。
   成功标准：第 5 节的错误文案表可直接被工程师抄进 `CODE` 表，无需二次翻译。

**本轮明确不做**：硬件旋钮与 S1–S8 真机输入（页签内键盘事件模拟，交互路径全覆盖）；风格样片真图（CSS 色板占位）。

## 2. 用户流程（页签内 7 步主流程）

### 0. 全局常驻元素（7 步共用）

| 元素 | 位置 | 内容 |
| --- | --- | --- |
| 阶段指示条 | 顶部 | 一行 5 段：`素材 → 风格 → 强度 → 生成 → 结果`，当前段高亮，已完成段打勾 |
| 当前参数摘要 | 顶部右侧 | 「赛博霓虹 · 强度 55% · 2K」——中文，不显示 `cyber-neon` 这类 id |
| 动作提示条 | 底部常驻 | 「按 Enter 生成：赛博霓虹 / 强度 55% / 1 张主体图」——**下一次按下会发生什么** |

**本轮按键约定**（真机未接入，键盘模拟；页签内「⌨ 硬件键」开关可关）：

| 键盘 | 对应硬件 | 语义 |
| --- | --- | --- |

### 1）素材区（browse）

- **用户看到什么**
  - 一块虚线拖拽区，文案：「把图片拖进来，或按 Ctrl+V 粘贴剪贴板里的图（最多 4 张）」。
  - 已加入的图以缩略图横排显示，第一张默认标「主体」，其余标「参考」。
  - 底部动作提示条：「按 Enter 进入风格选择」。
- **用户能做什么**
  - 拖拽文件 / `Ctrl+V` 粘贴 / 点「选择文件」按钮 → 加入素材（上限 4 张，第 5 张被拒）。
  - 点缩略图上的「设为主体」→ 切换主体图。
  - `1`–`4` 选中第 N 张，`Delete` 删除选中，`Esc` 清空全部。
- **系统给什么反馈**
  - 加入成功：缩略图带一次 200ms 的高亮描边动画；计数变化「素材 2 / 4」。
  - 第 5 张：拒绝并提示「素材最多 4 张：先删掉一张再加。」
  - 单张超过 900KB 或 4 张合计超过 2.4MB：提示「图片太大：单张超过 900KB（或 4 张合计超过 2.4MB）。请先压缩到长边 1600 像素以内再试。」
  - 超大原图（≥8192px）解码失败：提示「这张图太大，浏览器解不开。请先压缩到长边 1600 像素以内再试。」
  - 粘贴的不是图片：提示「剪贴板里没有图片。先复制一张图片再粘贴。」

### 2）选风格（browse → adjusting）

- **用户看到什么**
  - 10 个风格卡片宫格。**每张卡片必须同时有：中文名 + 一句话风格描述 + 配色色板**（见第 4 节）。
  - 不允许只给色块不给文字——只给色块违背「知道自己正在调什么」。
  - 当前选中的卡片有边框高亮；底部动作提示条实时更新：「按 Enter 生成：复古胶片 / 强度 50% / 1 张主体图」。
- **用户能做什么**
  - 鼠标点击任一卡片；或 `←` `→` 在 10 个风格间移动（循环）；或 `1`–`9`、`0` 直接跳到第 N 个。
  - `Enter` 确认并进入调强度；`Esc` 退回素材区。
- **系统给什么反馈**
  - 选中即生效（无需按 Enter 才能看到选中态），顶部参数摘要与底部动作提示条同步更新。
  - 底部追加一行该风格的适配提示，例：「复古胶片：很适合人像和宠物」。
  - 未选风格就按 `Enter`：不进入下一阶段，提示「先选一个风格，再调强度。」

### 3）调强度（adjusting）

- **用户看到什么**
  - 一条 0–100 的强度滑杆 + **中文档位名**（不只是数字）+ 一个数值。
  - 三档预设按钮：`轻度点缀（25）` / `平衡融合（50）` / `大改风格（80）`。
  - 底部动作提示条：「按 Enter 生成：赛博霓虹 / 强度 55% / 1 张主体图」。
  - 生图服务状态徽标（右上角）：`可用` / `未自检` / `不可用`（点它跑一次 `doctor`）。
- **用户能做什么**
  - `←` `→` 调 ±5，`Shift+← →` 调 ±1；鼠标拖滑杆；点三档预设。
  - `Enter` 生图；`Esc` 退回选风格。
- **系统给什么反馈**
  - 数值变化时，档位名实时联动：`0–30 轻度点缀` / `31–69 平衡融合` / `70–100 大改风格`。
  - 已到边界：到 0 提示「强度已是 0%，不能再弱了。」；到 100 提示「强度已是 100%，再高会把原图糊掉。」
  - 超过 85 时给一次善意警告（不阻断）：「强度超过 85 会大幅改变原图构图，人脸可能变形。」

### 4）生图（generating）

- **用户看到什么**
  - 全区域切换为生成态：进度条（不确定态）+ 倒计时「已等待 12 秒 / 上限 300 秒」+ 一行说明。
  - 明确写出不可取消：「生成中，不可取消（上限 300 秒）。请等待结果。」
  - 生图按钮与所有编辑类按钮置灰。
- **用户能做什么**：只有等待。
- **系统给什么反馈**
  - 期间按任何生成类 / 编辑类键：一律吞掉，提示条原地刷新为「生成中，不可取消（上限 300 秒）。请等待结果。」
  - 成功 → 进入「结果放大」。
  - 失败 → 进度区原地变为红条错误态 + 「重试」「自检」两个按钮，文案按第 5.2 节错误码映射。
  - **首次生图的隐私告知**：第一次点生图时弹一次确认：「这张图会上传到火山方舟用于生成，不会用于训练。继续？」——勾选「不再提示」后不再出现。

### 5）结果放大（result）

- **用户看到什么**
  - 结果图大图（页签内浮层放大，非全屏）+ 与主体原图的并排/滑动对比。
  - 元信息行：`赛博霓虹 · 强度 55% · 2K · 用时 9.1 秒 · 278KB`。
  - 底部动作提示条：「按 S1 存进作品集 · 按 S2 换一种创意显示 · 按 S3 放弃并重来」。
- **用户能做什么**
  - 放大/缩小/拖动查看；左右分屏对比原图。
  - `Enter`(S1) 存进作品集；`2`(S2) 进创意显示；`3`(S3) 放弃；`Esc` 回素材区。
  - 导出到磁盘（`result.export`）。
- **系统给什么反馈**
  - 保存成功：缩略图飞入底部「作品集」角标的动画 + 「已存进作品集（12 条）」。
  - 未保存就切换风格/重开：拦截并提示「当前结果还没存进作品集：按 S1 保存，或按 S3 放弃并回到素材区。」
  - 已保存过：允许直接切换，不再拦截。
  - 导出成功：「已导出到 `…\easyop-stylecam\20260925-120000_cyber-neon.png`」（路径可点复制）。

### 6）创意显示（creative）

- **用户看到什么**
  - 6 种展示形态的切换器，当前生效的高亮；结果图以该形态呈现。
  - 建议 6 种（产品侧提案，待架构师确认，见第 6 节）：`① 原图对比 ② 拍立得相框 ③ 杂志跨页 ④ 色板拆解 ⑤ 胶片连拍 ⑥ 前后轮播`。
  - 底部动作提示条：「按 1–6 切换显示形态 · 按 S1 保存当前显示」。
- **用户能做什么**
  - `1`–`6` 或鼠标点击切换形态；`←` `→` 在 6 种间循环；`Enter` 保存当前形态；`Esc` 回结果区。
- **系统给什么反馈**
  - 切换即时生效，无网络请求、无等待。
  - 按了不存在的编号：提示「创意显示只有 6 种（1–6），当前是第 3 种。」
  - 某一形态渲染失败：提示「这个显示形态渲染失败了，换一种试试。」（不影响其他形态与已保存的结果）。

### 7）作品集（gallery · 叠加态）

- **用户看到什么**
  - 页签底部的常驻横条：最近若干条作品的 320px 缩略图 + 计数「作品集 12 / 30」。
  - 展开后为宫格，每条带：`缩略图 · 风格名 · 强度 · 日期`。
- **用户能做什么**
  - 点缩略图 → 在当前页签内放大查看（不重载、不重生图）。
  - 每条右上角 `×` 删除；`Esc` 收起。
- **系统给什么反馈**
  - 保存/删除后计数实时更新；空态文案：「还没有作品：生成一张，按 S1 存进来。」
  - 达到 30 条上限再保存：拦截并提示「作品集已满 30 条：删掉旧的再存。」（不做自动淘汰，避免用户丢图不自知）
  - 重启 easyop 后作品集仍在（缩略图持久化，原图只留磁盘路径）。

## 3. 15 条命令的分级与 `tools` 归属

### 3.1 判定口径

- **「需要页签上下文」= 是** → 命令执行依赖页签内的瞬时状态（当前选中素材 / 当前风格 / 当前强度 / 当前结果图 / 焦点元素）。
  这类命令从 ⌘SS 触发时拿不到上下文，会稳定返回 `NOT_READY`，**纯挫败感**，因此**一律不进 `tools`**。
- **「需要页签上下文」= 否** → 命令只读持久化数据（storage / 运行环境），从 ⌘SS 触发能给出一句可阅读的结论，**可进 `tools`**。
- **进 `tools` 的额外门槛**：返回值必须是「一句话可阅读摘要」，不能是数组或裸对象——⌘SS 里没有渲染容器，吐数组等于没反馈。

### 3.2 分级表

| # | 命令 id | 中文名 | 分级 | 需要页签上下文 | 建议进 `tools` | 理由 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `stylecam.state` | 状态查询 | P1 | 否 | **是** | 只读持久化状态，⌘SS 里给「素材 0 张 / 当前风格 复古胶片 / 作品集 12 条」这类摘要有用 |
| 2 | `stylecam.image.add` | 添加素材 | P0 | 是 | 否 | 依赖拖拽区/粘贴目标焦点 + 页签内的 canvas 缩图管线 |
| 3 | `stylecam.image.remove` | 删除单张素材 | P1 | 是 | 否 | 依赖「当前选中第几张」，⌘SS 无法表达 |
| 4 | `stylecam.image.clear` | 清空素材 | P1 | 是 | 否 | 清空的是页签内的瞬时素材列表，与持久化状态无关 |
| 5 | `stylecam.style.pick` | 选择风格 | P0 | 是 | 否 | 作用于当前会话的选中态；⌘SS 里选了也没地方显示 |
| 6 | `stylecam.strength.set` | 设置强度 | P0 | 是 | 否 | 同上；且强度是页签内的连续调节，不适合命令化搜索 |
| 7 | `stylecam.generate` | 生成图片 | P0 | 是 | 否 | 强依赖当前素材 + 风格 + 强度三元组，缺任一即 `NOT_READY` |
| 8 | `stylecam.result.save` | 存入作品集 | P0 | 是 | 否 | 结果图只在内存里，页签 dispose 后即失效 |
| 9 | `stylecam.result.export` | 导出到磁盘 | P1 | 是 | 否 | 依赖当前结果图；导出路径需要用户确认 |
| 10 | `stylecam.creative.render` | 创意显示 | P1 | 是 | 否 | 纯前端渲染，必须有一个正在展示的结果 |
| 11 | `stylecam.gallery.list` | 作品集列表 | P1 | 否 | **是** | 只读持久化作品集；但**返回必须是摘要句**，见 3.3 |
| 12 | `stylecam.gallery.remove` | 删除作品集条目 | P2 | 是 | 否 | 需要「删哪一条」的选中上下文；P2 可延后 |
| 13 | `stylecam.config.set` | 配置设置 | P1 | 否 | **否（有争议，见 3.3）** | 无上下文也能执行，但改配置后页签不会同步刷新，易造成「改了没反应」 |
| 14 | `stylecam.doctor` | 环境自检 | P0 | 否 | **是** | 排障入口；Key 无效 / 模型未开通是高概率问题，必须能在不开页签时自查 |
| 15 | `stylecam.hardware` | 硬件/按键输入 | P0 | 是 | 否 | 本轮键盘模拟的全部交互路径都走它；事件必须打到已挂载的页签视图 |

**分级汇总**

| 分级 | 条数 | 命令 id |
| --- | --- | --- |
| **P0**（缺了主流程走不通） | 7 | `image.add`、`style.pick`、`strength.set`、`generate`、`result.save`、`doctor`、`hardware` |
| **P1**（重要，可延后一个迭代） | 7 | `state`、`image.remove`、`image.clear`、`result.export`、`creative.render`、`gallery.list`、`config.set` |
| **P2**（锦上添花） | 1 | `gallery.remove` |
| 合计 | **15** | — |

**P0 定级说明**（为什么这 7 条不能少）：

- `image.add` / `style.pick` / `strength.set` / `generate` / `result.save` = 7 步主流程的五个必经动作，缺任一流程断裂。
- `doctor` 定 P0 而非 P1：计划第十一节的风险 5（Key 可能不是方舟的）与风险 6（model 未开通）都是高概率问题。
  没有 `doctor`，用户会卡在「点了生成没反应」而完全不知道原因 —— 这是最糟的挫败感。
- `hardware` 定 P0 而非 P2：本轮真机未接入，键盘模拟的全部交互路径都要经过它。它不是「锦上添花」，是本轮唯一的输入通道。

### 3.3 建议与计划的差异（1 处）

计划第 4 节已定「`tools` 只放 3 条：`doctor` / `state` / `gallery.list`」。
**产品侧同意这 3 条，且不建议增减**，理由如下：

1. **`gallery.list` 进 `tools` 有一个附加条件**：返回值必须是「作品集 12 条，最近 3 条：水墨国风·强度 70（09-25 14:20）、赛博霓虹·强度 55（09-25 12:03）、复古胶片·强度 30（09-24 20:41）」这样的一句话。
   若直接吐 12 条对象的数组，⌘SS 里等于没有反馈 —— 那它就不该进 `tools`。
2. **`config.set` 不进 `tools`**：它能无上下文执行（这是它与其它 11 条不同的地方），但改完配置后已挂载的页签不会自己刷新，
   用户在 ⌘SS 里改了「硬件键开关」，回到页签发现键还是没反应 —— 这是比 `NOT_READY` 更糟的挫败感。**保持不进。**
3. **其余 12 条一律不进**：它们从 ⌘SS 触发只会稳定拿到 `NOT_READY`。
   若宿主后续给插件加了「无上下文时的兜底提示」能力，可在那时再评估 `image.add`（可以退化成打开文件选择器）。

## 4. 10 组风格的产品侧定义

> 给工程师的说明：下表是**给用户看的中文文案**，直接用于风格卡片的一句话描述与适配提示。
> 英文 prompt 片段与配色色板是工程侧的活，本文不给。
> 卡片要求：**中文名 + 一句话描述 + 色板**三者同时出现，不允许只有色块。

| # | 风格 id | 中文名 | 一句话风格描述（给用户看） | 适合什么素材 | 不建议 |
| --- | --- | --- | --- | --- | --- |
| 1 | `cyber-neon` | 赛博霓虹 | 深蓝紫底上洋红与青色的霓虹描边，暗部会发光，像雨夜的赛博都市 | 城市夜景、街拍、带灯光的人像、科技产品 | 白天的风景照（会显得脏） |
| 2 | `retro-film` | 复古胶片 | 柯达胶卷的暖黄偏色，带颗粒和轻微褪色，像 90 年代的家庭相册 | 人像、宠物、旅行记录、日常抓拍 | 需要精确还原色彩的产品图 |

## 5. 状态与降级

### 5.1 5 个阶段 × 4 类异常 —— 提示文案表

状态机：`browse → adjusting → generating → result → creative`（`gallery` 为叠加态，不参与流转）。
下表每一格都是**可直接抄进 UI 的中文文案**。

| 阶段 | 按错键 | 没素材 | 没 Key / Key 无效 | 生成失败 |
| --- | --- | --- | --- | --- |
| **browse**<br>素材区 | 按到结果区/创意区的键：<br>「当前在素材区：先拖入或粘贴一张图，再按 → 进入风格选择。」 | 常态，不报错。空态文案：<br>「把图片拖进来，或按 Ctrl+V 粘贴剪贴板里的图（最多 4 张）」 | 不发请求，不适用。<br>但右上角常驻徽标：<br>「生图服务：未自检 · 点这里自检」 | 未发起，不适用 |
| **adjusting**<br>选风格/调强度 | 没选风格就调强度：<br>「先选一个风格，再调强度。」<br>强度到 0：<br>「强度已是 0%，不能再弱了。」<br>强度到 100：<br>「强度已是 100%，再高会把原图糊掉。」 | 从 browse 跳过素材直接进 adjusting：<br>「还没有素材：先加一张图，才能调风格和强度。」<br>并自动退回 browse | 不发请求，不适用。<br>但若上次 `doctor` 已知 `KEY=0`，调节区顶部常驻黄条：<br>「生图不可用：API Key 无效，点『自检』查看原因。」 | 未发起，不适用 |
| **generating**<br>生成中 | 所有生成类/编辑类键一律吞掉，提示条刷新为：<br>「生成中，不可取消（上限 300 秒）。请等待结果。」 | 理论上不可能（进 generating 前已校验）。防御文案：<br>「素材丢失，已回到素材区。」 | 前置阻断：若本地缓存的 `doctor` 结果为 `KEY=0`，**不进入** generating，直接给黄条：<br>「没有可用的生图 Key，先点『自检』修复，再生成。」 | 进度区原地变红条 + 「重试」「自检」两个按钮，正文按 5.2 错误码映射，例：<br>「生成失败：方舟返回 ModelNotOpen，去控制台开通 Seedream 模型」 |
| **result**<br>结果放大 | 未保存就切风格/重开：<br>「当前结果还没存进作品集：按 S1 保存，或按 S3 放弃并回到素材区。」<br>已保存过则不再拦截 | 不适用（结果已在） | 不适用（已出图） | 失败不会进入 result。若保存阶段失败：<br>「保存失败：写不了文件到输出目录。换一个输出目录后重试。」 |
| **creative**<br>创意显示 | 按了不存在的编号：<br>「创意显示只有 6 种（1–6），当前是第 3 种。」<br>还没结果就进创意区：<br>「还没有可展示的结果：先生成一张。」 | 不适用 | 不适用 | 创意显示是纯前端渲染，不发请求。<br>渲染失败：<br>「这个显示形态渲染失败了，换一种试试。」 |

**阶段回退规则（跨阶段通用）**：

- 任何阶段按 `Esc` → 退回上一阶段，`browse` 的上一阶段是它自己（不退出页签）。
- `generating` 不响应 `Esc`（不可取消），文案已在表中。
- 页签切走再切回：恢复到 `browse`，内存中未保存的结果丢弃。
  切回时若上次有未保存结果，给一次温和提示：「上次生成的结果没有保存，已经丢弃了。下次记得按 S1 存进作品集。」

### 5.2 错误码 → UI 文案（UI 文案唯一依据）

> 工程师直接把右列抄进 `CODE` 表。文案里的数字、路径、控制台名称必须与脚本实际行为一致。

| 来源 / 错误码 | 界面文案（逐字使用） |
| --- | --- |
| 无可用 Key（`E_NO_KEY` / `KEY=0`） | 「没有可用的生图 Key：easyop 配置里的 `llm_api_key` 不是火山方舟的 Key。去方舟控制台新建一个专用 Key，或填进插件目录的 `tools/stylecam_io.env`。」 |
| 模型未开通（`ModelNotOpen`） | 「生成失败：方舟返回 ModelNotOpen，去控制台开通 Seedream 模型。」 |
| 鉴权失败（`E_API` + HTTP 401/403） | 「生成失败：方舟鉴权失败（401）。Key 无效或已过期，点『自检』重新探测。」 |
| 限流（`E_API` + HTTP 429） | 「生成失败：触发方舟限流（429）。等 30 秒再试一次。」 |
| 其它 API 错误（`E_API` + 其它码） | 「生成失败：方舟返回错误 `<code>`：`<message原文>`。点『自检』看完整输出。」 |
| 网络超时（`E_NET`） | 「生成失败：连不上方舟（网络超时 120 秒）。检查网络或代理后重试。」 |
| 图片不合规 / 过大（`E_IMG` / `IMG_TOO_LARGE`） | 「图片太大：单张超过 900KB（或 4 张合计超过 2.4MB）。请先压缩到长边 1600 像素以内再试。」 |
| 返回解析失败（`E_PARSE`） | 「生成失败：方舟返回的内容解析不了。已把原始返回写进日志，点『自检』查看。」 |
| 写盘失败（`E_IO`） | 「保存失败：写不了文件到输出目录。换一个输出目录后重试。」 |
| 本地存储失败（`E_STORAGE`） | 「本地存储读写失败：作品集这次没能存下来。重启 easyop 再试。」 |
| 脚本超时（`IO_TIMEOUT`） | 「生成超时：超过 300 秒还没出图。换小一点的尺寸，或稍后重试。」 |
| 无结果（`NO_RESULT`） | 「生成结束但没拿到图：脚本输出不完整。点『自检』看日志。」 |
| 素材超限（`MAX_IMAGES`） | 「素材最多 4 张：先删掉一张再加。」 |
| 缺上下文（`NOT_READY`） | 「这个命令要在『风格调色盘』页签里用：先打开左侧的风格调色盘页签。」 |
| 未知退出码 | 「生成脚本异常退出（代码 `<exitCode>`）。点『自检』看完整输出。」 |
| 参数错误（`E_ARGS`） | 「插件内部参数错误（`E_ARGS`）。这属于缺陷，请把日志发给开发者。」 |

**错误展示的统一规则**：

1. 错误一律显示在**用户刚操作的那个区域**（素材区错误显示在素材区，生成错误显示在进度区），不要用全局弹窗。
2. 每条错误最多两行：第一行是「发生了什么」，第二行是「你现在该做什么」。
3. 「自检」按钮永远出现在错误旁边 —— 用户不需要记住怎么排查。
4. 禁止出现「操作失败」「请求异常」「发生错误」这类无信息量的文案。
