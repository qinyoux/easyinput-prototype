  ⇒ **`6768e93` 提交的就是坏版本**，故事后 `git status` 显示"干净"

### 三条教训（都要记住）

1. **`git status` 干净 ≠ 提交了正确内容。**
   `add` 之后工作树的任何外部改写都会被 commit 静默吞掉，且事后无痕迹。
   ⇒ 提交后**必须复跑 `version:check`**，这是唯一能暴露它的动作。
2. **多 agent 并行时，`git add` 与 `commit` 之间存在被他人中途改写的窗口。**
   本次踩的正是这个窗口（我从干跑到 commit 之间隔了几十秒）。
   ⇒ 大提交要么尽快、要么提交后立即复查一致性。
3. **`core.autocrlf=true` 不是本次元凶。** 已验证：提交后工作树仍是**纯 LF**
   （CHANGELOG/README/tts.rs 的 CR 计数均为 0），git 只在 checkout 时转换。

### 为什么不能从 git 恢复

- `git cat-file --batch-all-objects` 里 CHANGELOG 只有**一个** blob（171847 B）
  ⇒ 好版本（178489 B）**从未进过 git**（写入发生在 `add` 读取之前）。
- 排除本仓库工具：`.git/hooks/` 为空、无 `.gitattributes`、
  `scripts/version.mjs::insertChangelog/insertReadme` 是**只插不删**（`raw.slice(0,at)+block+raw.slice(at)`）。
- ⇒ 怀疑**并行 agent 会话**。同类故障 2026-09-23 14:57 已发生过一次（那次清回 v0.32.0）。
