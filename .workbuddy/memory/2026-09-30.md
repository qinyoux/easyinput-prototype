### 判据：怎么分"必要说明"与"详细内容"

用户原话是"默认仅展示必要的选择或填写说明及功能介绍，点击后再展开详细内容"。
落地判据 —— **这段字在回答"怎么填"还是"为什么这么设计"**：前者常显，后者收起。
- **常显**：字段 label / 输入框；字段级提示（如"资源 ID 与音色必须同版本"，
  看不到就会填错）；每个 § 的一句功能摘要。
- **收起**：原理 / 传输方式 / 采样率 / TUI raw mode / 历史沿革。

⛔ **折叠 ≠ 删除**：原文一字未改，只移位。仅三处把段落首句提为按钮文案。
💡 就地折叠的按钮文案**直接写成用户心里那句疑问**（"为什么这里没有开关和配对按钮"、
"接好之后还要每次手动连吗"），比千篇一律的"更多"有用得多。

### 折叠原语的三条硬约束（`src/components/Collapsible.tsx`，228 行）

1. **触发器必须是真 `<button>`**（不是 `div+onClick`）：Tab 可达、Enter/Space 可用、读屏能报状态。
2. **⛔ 不能嵌套 button** —— HTML 不允许，WebView 会把它拆开。**任务历史标题栏里原本就有
   一个「刷新」按钮**，所以折叠按钮必须与它**并列**，且点「刷新」不能切换折叠。
   → 通用教训：**给既有标题栏加交互前，先看那一行里已经有什么可点的东西。**
3. **内容体用 `hidden` 而不是条件渲染**：条件渲染会让 `aria-controls` 指向不存在的元素。
4. 默认收起**只影响"第一次看到"**：手动切过之后按 localStorage 记住
   （键名 `easyop.collapse.<id>`，**改名 = 重置用户偏好**）。读写全 `try/catch`，
   隐私模式下静默降级为"不持久化"。

### ⚠️ 多 agent 共树：这次差点把别人的改动固化进 git 历史

工作区里另一 agent 留下了未提交的改动，**其中三处会污染我的提交**，全部拦下：

1. **`README.md` 被 markdown 格式化重排**（表格对齐 + 行尾双空格软换行）——
   仅 README 就有 **20 个 hunk 且行数对称**（`@@ -1,22 +1,22 @@`）。
   长得像行尾符问题，但实测工作区与 HEAD **都是纯 LF（0 个 CRLF）**，是真实内容替换。
   → **教训：看到"行数对称的大批 hunk"，先验行尾符；排除了才是内容重排。**
2. **`package.json` 混入另一 agent 的 `plugins:test` 串接 + `plugins:build:stylecam`**，
   引用尚未提交的 `plugins/builtin/stylecam/**` ⇒ 一起提交会让 `npm run plugins:test`
   指向不存在的文件（**提交后立刻坏，且不报错在 diff 里**）。
3. **`CHANGELOG.md` 混入另一个版本节（0.39.0）**，同样未提交。

**解法：不用 `git add` 整文件，改用「HEAD 版 + 仅我这一节/这一项」构造 blob 直接写 index。**

```bash
# 0) 从 HEAD 取基线 —— 必须用 bytes 取，text=True 会在 Windows 把 \n 转成 \r\n
git show HEAD:README.md > base.md
# 1) python 把"我的节"插到锚点之前（锚点 = 基线里紧邻的上一个版本标题）
new = base[:i] + mine + base[i:]
# 2) 直接写 index，**全程不碰工作区**
blob=$(git hash-object -w new.md)
git update-index --cacheinfo 100644,$blob,README.md
```

结果：`git diff --cached --stat` 显示 CHANGELOG +58 / README +9（**纯新增、零删除**），
`package.json` 只有 2 行（1 增 1 删 = 版本号）。**工作区完全没被碰** ⇒
别人的改动原封不动留着，等它自己的作者提交。
脚本落在 `%TEMP%/easyop_stage.py`、`easyop_stage_pkg.py`（可复用）。

### 任务台页真实结构（`DeskView.tsx`，1335 行，7 个 `desk-section`）

### ① 执行器：**保留**

**⛔ 用户前提错**："执行器的配置已能在槽位和按键映射中看到" —— 不成立。
- 「按键重映射」页 = `KeyEditor`，只有一句"槽位必须绑 CLI 形态的执行器"，不编辑执行器。
- 任务台「槽位」板块只显示 `mode`/`detail`（如"按能力「推理」挑选：可用候选 2 个"），不含执行器清单。
- **唯一**能看到执行器名的是「设置 → 槽位绑定」（`DeskSlotBinding`，下拉列 `cfg.drivers`），
  但那编的是**绑定关系**；该文件 L225 原文自证："执行器本身在别处配"。
- 执行器**本体**配置（命令/参数/超时/完成判定/门禁/启用）唯一入口 = 「模型配置 → §4」。

**任务台「执行器」板块不是配置表单，是运行时健康看板**，4 类别处完全没有：
`schedulable`(可调度 vs 不会被执行) / `confidence`(已校验 vs 未校验)+完成信号 /
**`errors`(✕ 硬错误 = 被拒绝调度的原因)** / **`warnings`(软警告)**；另有「检查」静态探测。
→ 移除丢的不是配置，是**诊断**。DeskView L1299 注释自己钉着："否则用户只会看到『点了没反应』"。
→ 优化方向：无异常时折叠、**有硬错误自动展开**。

### ② 运行时（队列+未读）：**不合并，但改红绿灯 ✅**

**槽位板块里已经有每槽明细**（`待执行 N`/`未读 N`/`播放中`/正在执行行+取消/排队列表+撤销/取租约）。
运行时板块提供的是槽位里**没有**的：跨槽汇总、**第 5 颗灯亮灭**、**喇叭归属**、idle 与 busy 的区别、活跃执行器名。

→ **不合并的理由**：第 5 灯与喇叭是**全局独占资源**，物理上不属于任何单槽；塞进槽卡会误导
（"这灯是 S2 的？"），且槽卡已有 6~7 个元素，叠加全局数据只能"重复 4 遍"或"只挂一张卡"，都别扭。
→ **红绿灯赞成**：三态 空闲(绿) / 有积压(黄) / 执行中(红) + 一行摘要。
  这正好解决后端注释反复强调的坑——"'有积压没在跑'时 busy=灭、idle=否，两种情形不是一回事"，
  **文字难表达，颜色一望即知**。
→ ⚠️ 硬约束：**灯色不能在纯前端推导**（同"字幕显隐只由后端决定"的既有教训）——
  应由后端给出 `idle|queued|busy` 一档语义，前端只做映射。

## 三态灯的设计判据（照此改，别重新发明）

- **判据在后端，前端只做颜色映射**。新增 `LightState{Ide, Running, Backlog}` +
  **纯函数** `from_queue(running_count, total_pending)`（`agent_desk/state.rs`），
  `RuntimeSnapshot` 加 `light` 字段。前端 `LIGHT_UI` 只做"档位 → 文案/颜色"。
  ⛔ 不许前端从 `busy`/`idle`/`total_pending` 自己推 —— 那是**第二份判据**，
  后端一改就会静默不一致（与"字幕浮层显隐"同一个坑）。
- **三档不是"忙/闲"两档**：`Backlog`（有积压却没人跑）就是原先
  "`busy==false` 而 `idle==false`" 那个组合 —— 它在平铺计数器里是两个各自为真、
  加起来自相矛盾的词，这是"颜色一望即知、文字说不清"的典型。
- **`Running` 用橙（`--accent`）不用红**：红灯在中文语境读作"坏了"，
  而"有任务在跑"是最正常的时刻，会让人去排查不存在的问题。
- ⚠️ `light` 参与 `RuntimeSnapshot` 的 `PartialEq`。漏进去 ⇒ 灯停在旧档位不动而
  其它字段看着一切正常 ⇒ 已由 `light_change_alone_triggers_an_event` 守住。
- ⚠️ 动画光晕颜色靠 `--glow-rgb` **按档位切换**，keyframes 里**不能**写死 `accent-rgb`
