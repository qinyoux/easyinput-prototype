## easyop v0.44.0：关闭任务台播报排队机制的三条遗留

钦友点名要求写清楚的三条遗留（v0.42.0 CHANGELOG「未完成」里的）已全部关闭。
**关键发现：第 1、2 条上一轮（v0.43.4 标记）已在工作树实现，第 3 条真没做**——
`DeskSnapshot.notice_queue` 有数据但前端**从未渲染过**，且快照 5s 轮询、
等待期完全无反馈。所以本轮实际工作是：修编译错误 + 补第 3 条的实时可见性。

- **先修编译错误**：`EnqueueDecision::Drop { reason: _ }` 用 `_` 做表达式模式匹配
  ⇒ `E0599: _ can only be used on the left-hand side of an assignment`，`cargo test` 全挂。
  改 `matches!(..., EnqueueDecision::Drop { .. })`。教训：枚举变体带字段时，
  测试里想"忽略字段"必须用 `matches!` + `{ .. }`，不能写 `{ reason: _ }`。
- **遗留 1（进度类不排队）→ 收敛入队**：纯函数 `enqueue_decide` 返回
  `Append / Replace / Drop{reason}`。规则：终态必排队；进度类队里有终态 ⇒ 过期丢弃
  （FIFO 下永远排在终态后），队里有同类 ⇒ Replace 只留最新，空队列 ⇒ Append。
  **判据是价值的时间衰减曲线**（终态不衰减 / 进度衰减 / 事件在前端实时可见）。
- **遗留 2（只报条数不报槽位）→ 记明细**：`notice_dropped` 从 `AtomicUsize`
  改为 `Mutex<Vec<DroppedNotice { kind, slot }>>`；`merged_reminder_text` 输出
  "还有 2 条任务结果未播报（S1 任务已完成、S3 任务失败），请点击查看。"，>3 条退化纯条数
  （TTS 按字数计费）。进度类被丢**不记**明细（过期进度报进提醒是噪音）。
- **遗留 3（队首等待无实时进度）→ 新事件 `agent-desk-channel`**：
  - `project_channel(mgr)` 是喇叭实况的**唯一投影**，快照（5s）与事件**同源**取值 ——
    两处各算一遍会漂移成"喇叭响着 A、界面写着在播 B"，这类 bug 排查时最难重现。
  - **刻意不并入 `agent-desk-state`**：后者由任务状态驱动，而播完/入队发生在
    任务状态完全没变的时刻；等它再变，等待期已经结束。**触发模型不同必须分事件**。
  - "真变化才发"用**内容比对**（`PlayingView`/`NoticeQueueItemView` derive `PartialEq`
    + `last_channel_state`），**不用版本号** —— 并发播放下版本号必然错序。
  - 推事件点：`speak_notice` 起播/清场（为此给它加了 `app` 参数，播放起止都在它内部）、
    `desk_render_result` 接管/清场、`enqueue_notice` 入队后、`drain_notice_queue` 收尾。
  - ⚠️ **`enqueue_notice` 必须在释放 `notice_queue` 锁之后才推事件**，
    否则 `emit_channel_state` 重入同一把非阻塞 `Mutex` 直接死锁。
    实现上把决策结果先记成 `queued` 布尔再出作用域。
  - 前端：`channelSeenRef` 只让快照做**初值兜底**，收到过事件后不再覆盖 ——
    否则请求往返延迟会让界面在"在播/空闲"之间来回跳，比慢 5 秒更困惑。
- 验证：`cargo test --lib` **532 passed / 0 failed**（agent_desk 289）、
  `npm run build` ✅、`tsc --noEmit` 无错、`version:check` ✅ v0.44.0。
- 文档同步：设计方案 §9.2（排队三态表 + 投影同源）与 §19 第 6 条（三条划掉并写明怎么修的）。
